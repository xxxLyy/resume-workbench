## 0. 一句话结论与产品目标

先修断掉的 PDF 渲染链路（S0），抽主题层做地基（S1），全量换肤（S2），把"段落→语义区域绑定"立为内容模型一等公民（S3），在其上建岗位适配核心链路（S4a）与流水线增强（S4b），再补引导向导（S5）、模板库（S6）、语音/截图输入（S7）、网申包（S8）、录音复盘（S9）。**一次只做一个 S；按里程碑交付，每个里程碑后都可停下持续使用。** 素材库升级为**事实与表达分离**（S3）；岗位适配以**要求—证据对应表**与**本次定制要求卡**驱动，而非单一匹配分（S4a）。

**产品目标**：同时服务两类人 —— 老用户快捷编辑（打开即改、改完即导出）与新用户可选引导（向导可跳过）。任何新增功能**不得强制重复建档、不得要求确认未变化的信息、不得强制走完整流水线**。

## 2. 架构决策（不要翻案，除非有新增事实）

### 决策 1：换肤走"主题层"，不硬改颜色

`docs/*.html` 为自包含文件（样式内联），快照与投递存档必须能独立渲染。故把简历正文样式抽为可切换 `themes/<name>.css`，文档只留注入点；应用界面走 CSS 变量 token。S2/S6/S4a 共用此机制。

**新旧快照均能独立渲染：新快照冻结主题 CSS、排版参数及必要资源；主题或排版变化必须使旧 PDF 标记失效**（不得用旧 PDF 冒充新样式产物）。
否决备选：直接改内联样式 —— S4a/S6 落地必返工。

### 决策 2：杂志感只作用于应用界面；投递用 PDF 保持 ATS 干净

投递 PDF 的读者是 HR 与 ATS。应用界面全量杂志编辑感；投递默认 PDF = 干净单栏（`themes/resume-classic`）；杂志感作为可选"展示版"模板进 S6。

### 决策 3：区域绑定是内容模型一等公民（v2 新增，v3 修订）

段落 → 语义区域的绑定关系持久化在 `docs-meta.json`；**绑定以非视觉标识或外部映射实现，保持可见布局与直接编辑体验**（不污染正文 HTML，保证快照/存档独立渲染）；预览按区域着色**仅编辑器可见**，不进 PDF；岗位流水线的"只改写目标区域、保留其余"、区域级分析、定向改写全部以绑定为锚点。未绑定段落进"待绑定"队列。
否决备选：继续用选区（selection）做锚点 —— 选区是瞬态的，无法支撑跨会话的区域对话与流水线账目。

### 决策 4：网申只做本地包；公司墙与浏览器插件不做（v2 新增）

- 网申包 = 本地维护的"自己的通用信息表 + 按公司字段包"，一键复制/整包导出。
- 公司卡片墙/秋招信息源不做：重数据维护、易过期、与核心闭环无关。
- 浏览器插件真站自动填表不做：跨站注入的安全面与可靠性成本高于收益；开源后作为**独立扩展包**由社区或后续单独立项，不进核心仓库。

### 决策 5：既有编辑方式为一等公民，新能力只叠加不替换（v2 新增，用户明确要求）

用户现有的改简历方式必须原样保留，所有新能力在其上叠加：

- **直接点击正文编辑**（contenteditable）保留；区域绑定保持可见布局与直接编辑体验，允许非视觉标识或外部映射，不锁定段落、不改变阅读顺序。
- **章节/条目级积木**（↑↓ 排序、👁 隐藏、添加章节）保留。
- **选区改写**（选中文字 → 浮动工具条）保留；S3 的"修改模式"是新增并列入口，不取代选区改写。
- **排版面板 / 缩放 / 数值输入**保留；S4a 的自动排版只产出建议 op 进统一撤销栈，不自动接管排版。
- **新建文档多入口**保留：空白文档、PDF/截图导入照旧；S5 向导是可选入口，可跳过、可暂存、可对已有简历预填补缺。
- **岗位草稿现状流程**（创建 → 审阅接受/撤销 → 冲突门控 → 导出）语义不变；S4a/S4b 是其上的增强。
- **统一撤销栈、历史快照回滚、多标签冲突保护**继续覆盖全部程序化修改。

### S3 · 区域绑定与区域级分析（4–6d，依赖 S1）

### S4a · 岗位适配核心：生成→审阅→导出（6–8d，依赖 S3）

- 范围：在现有岗位草稿+审阅门控之上：① 基于 S3 绑定只改写目标区域、明确保留个人与教育；② 段级账目（共 N 段 改写 X 保留 Y）；③ 三段源对比（原文/候选/已接受）+ 版本选择应用；④ 空间预算/自动排版（字号/行高/段距 op，不靠极小字号硬塞）含**迭代上限**与**无法达标时的处理方式**（提示手动取舍、或允许超页导出并明确标注）；⑤ 输入支持 JD 文本/链接；JD 截图入口**依赖 S7b**，未就绪时隐藏而非报错；⑥ **本次定制要求卡**（生成前，高级设置默认折叠）：本次重点（算法效果/端侧部署/工程平台/大模型应用）、必须保留的项目、不希望强调的经历、修改幅度（轻度精简/重点调整/重新组织）、页数目标（默认两页）；可存为常用岗位预设，但每次仍可调整、不替代具体 JD 分析；预设入口在 S2 首页与编辑器；⑦ **岗位要求—经历证据对应表**（主审阅产物，替代单一匹配分）：每行 = 岗位要求 / 当前证据 / 状态（已覆盖 = 做过且写清楚；待补充 = 可能做过需你补；表达不充分 = 做过没写清楚；暂无证据 = **当前已确认来源中未找到证据**，允许补充、不能推断用户没做过、更不能自动补写）/ 操作；点击要求定位到相关经历，点击建议可见"为何用此项目、为何隐藏另一项目"；任务组织借鉴 Teal/Huntr，本项目深化证据来源与修改可追溯性；⑧ **局部重新生成与手改保护**（早于复杂并行改写）：对指定项目/段落重新生成；"此段保留我的版本"标记（S3 承载）生效即跳过；提交补充事实后只更新受影响建议；已接受/已拒绝/已手改状态明确；每次生成绑定起始版本；生成期间同区域又被修改时结果进候选区供比较、不覆盖当前正文；拒绝建议可选原因（改变原意/太空泛/过度夸大/不符合我的表达），反馈用于当前任务后续生成，存为长期偏好需用户主动选择；⑨ **审阅面板做成有终点的任务**：待处理数量按事实冲突/隐藏经历/普通表达分类；筛选"仅重点/仅本次变化"；下一条/上一条与键盘操作；按项目接受普通修改；关闭后再进入回到上次位置；正文后来变化导致失效的建议明确标出；完成标准明示 = 事实冲突已解决 + 必要重点已处理 + 当前正文已保存 + PDF 对应当前版本；不为消除提示而强制确认与当前任务无关的素材与绑定；⑩ **排版问题定位**：哪个项目跨页、哪个标题与正文分离、哪页内容过少、哪些段落过长或重复、应用某排版建议前后的实际页数变化；点击问题定位；内容精简与排版调整分别展示以便判断代价；⑪ **确定性内容检查**（校验阶段与导出检查共用，不依赖 AI）：公司/项目名写法不一致、日期格式不统一或明显倒序、联系方式格式异常、链接格式错误、重复段落、未替换占位符、中英文标点与单位不一致；"熟悉/精通/负责"大量重复仅作风格建议；经历时间重叠与不同岗位职位差异只提示核对不自动改；结果分三级 = 需要修复/建议核对/风格建议；⑫ **版本状态展示**：母版/岗位草稿/审阅中/可投递/已用于投递/已归档（S1 状态机）；母版更新时提示"该岗位版来源较旧"并可查看差异，不自动同步岗位版。
- 硬约束：事实护栏与冲突门控不变，并**升级到事实层**（S3 事实与表达分离）：换表达不换事实 —— 不得把"模型推理延迟"改成"系统端到端延迟"、不得把团队成果改成个人成果；数字相同不代表事实相同，事实层校验补现有"新增数字/丢失日期"检查的缺口，同时减少正常改写被误拦截；所有改写仍走审阅接受/撤销；无模型时明确降级且草稿/母版不受影响。
- 验收：证据对应表四态齐全且可定位/可追溯；账目数字与实际改动一致；三段对比可回溯；局部重生成不触碰保留段与手改段；审阅面板有明确终点与恢复位置；排版诊断可定位且页数变化如实；确定性检查三级分类正确且不误改；达到迭代上限仍不达标时有明确出路而非假成功；现有创建→审阅→导出路径语义不变（决策 5）。
- 不做：不做"一键全自动不接受审阅"；不做录用概率/通用 ATS 分数。

### S7 · 语音输入 + 截图导入（3–4d；硬依赖 S0；任务管理依赖 §3.2、编辑器区域入口依赖 S3 —— 未就绪时以最小内联实现与全局入口独立交付；两个可独立交付子阶段）

- **S7b 截图**：复用 `importer.mjs`，"PDF 提取文本"替换为视觉模型读图；**模型能力检测**，处理位置 = 服务端 LLM；**先对照校正再确认**（原文 vs 识别结果对照，可改后确认）；产出走现有结构化与"待结构化"状态；入口放首页导入折叠内并列，不抢主位。

- 任务管理：复用 §3.2 AI 任务管理最小集（模型/状态/超时/取消保留已完成/只重试失败/防重复/用量如实）。
- 降级：无视觉模型 → 仅存图+提示手动录入，不假装成功。
- 验收：S7a/S7b 可分别独立交付；截图→结构化进模板；暂存/对照校正流程可用；降级文案明确；stub 视觉模型进 `test.sh`。
- 不做：图像预处理（去歪斜等）。

### S8 · 网申包（2–3d；核心网申包无依赖可插队，分享副本导出依赖 S1）

- 范围：`/apply-profile`：自己的通用信息表（姓名/电话/邮箱/教育/经历纯文本版/项目纯文本版/自评等）+ 按公司字段包（每家公司可覆写字段、备注网申地址）；**每个字段标注来源 = 通用母版 or 岗位版**，并支持三态：**跟随来源 / 手动覆写 / 恢复跟随**；**期望薪资等独立字段不强行从简历派生**（独立维护）；单字段一键复制 + 整包导出（JSON/纯文本）；漂移有提示。**分享副本导出**：隐藏指定字段生成独立预览/PDF、不修改原简历，导出前校验 PDF 文本层与附件确无被隐藏字段残留（避免仅视觉遮挡）；导出记录可查被哪些投递引用（S1）。
- 硬约束：不做跨站自动填表注入（决策 4）。
- 验收：复制/导出可用；三态切换行为正确；独立字段不被简历改动覆盖。
- 不做：公司卡片墙、秋招信息源、浏览器插件。

### S9 · 面试录音复盘（4–6d；依赖 S0、§3.2 任务管理、S3 素材结构）

- 范围：上传录音 → 转写 → 对照 JD+简历生成复盘；复盘页新增"录音"分区与现有数据分区并列；每条投递可挂复盘笔记（类别 笔试/面试、时间、标题、内容）；**删除规则统一：删除音频可保留转写；删除整条复盘才清理全部关联内容**；复盘意见附**转写时间戳**，支持**说话人标注与转写校正**；**复盘反哺准备**：输出被反复追问的项目、未解释清的指标、缺少个人决策与贡献的回答、需补充准备的知识点、下次练习问题及对应录音时间点；可一键转"待补充素材"或"下次面试准备"（与素材库轻量关联）；**一次口头回答不自动成为已核实事实，AI 复盘意见不直接覆盖原文**（确认步骤保留）。
- 转写选型：本地 whisper.cpp 优先（M5/16GB 可跑 small/medium）；云端 ASR 可选 profile。默认 small，限制单文件大小。任务具备**进度、取消、重启恢复与产物清理**；**不假设现有 job 队列可复用**，开工时先核实，缺则自建最小任务表；转写与复盘任务复用 §3.2 AI 任务管理最小集。
- 验收：真实录音（用户授权后）端到端出复盘；转写失败有明确状态；删除规则按上述逐条验证；任务取消与重启恢复有测试。
- 不做：实时录音/会议接管。

## 6. 执行约定

1. 一次只做一个 S；开工前写 `dev-docs/YYYY-MM-DD-<sN>-design.md`（spec）→ plan → impl → 验证，回写 §3.1 状态表。
2. AI/视觉/语音相关测试一律本地 stub，结论标注"模拟验证"；真实模型/真实录音需用户明确授权后才跑。**模拟测试通过不能代替真实模型质量验证。**
3. 每轮结束跑 `test.sh` + `test-structure.sh` + `test-render.sh`；真实数据指纹前后比对。
4. 编辑器模板版本升级必须走 `migrate-editor.mjs` 模式（先快照、幂等、护栏版本号）。
5. 侧边任务列表与 §3.1 状态表保持同步（2026-09-23 起约定）。
6. **既有编辑方式回归门槛（决策 5）**：每个 S 的验收必跑回归清单 —— 直接点击正文编辑、章节/条目积木（↑↓👁/添加章节）、选区浮动工具条改写、排版面板与缩放、统一撤销栈、历史快照回滚、多标签冲突保护。建议在 `test-editor.mjs` 立为常驻套件，任何 S 不得使其变红。
7. **里程碑验收**：每个里程碑用代表性岗位任务对比**成稿时间、人工修正次数、导出成功情况**；并单独安排**新用户独立完成任务**试用（M2 起必做）。
8. **贯穿工程要求**（不另开功能阶段）：保存一致性（正文/排版/绑定/审阅状态版本关系一致，部分写入失败可恢复）；性能（输入时不反复全量扫描与重建界面，重型 PDF/转写处理不阻塞编辑）；数据迁移（每次结构变更可备份/可验证/可回退，旧文档继续可读）；错误提示（明确区分保存/模型/PDF/网络失败并给对应操作）；可访问性（键盘完成主要流程，字号/对比度/焦点/减少动效均可用）；质量评估（用固定虚拟简历与 JD 验证事实保持/定位/撤销/分页/异常恢复，真实质量另行验证）。
