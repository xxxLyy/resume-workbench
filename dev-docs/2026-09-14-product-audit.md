## P0：先修复可信性

### 1. 保存期间输入被误判为已保存

位置：template.html:269–317。doSave 克隆版本 A 发出请求；用户继续输入 B 后，请求成功无条件 dirty=false，并清除本地恢复缓存。

隔离验证结果：submitted=VERSION_A，editor=VERSION_B_NEW_EDIT，dirty=false，state=saved，localRecoveryPresent=false。若自动保存计时器在 saving 期间触发，也不会重新排队。

建议：维护编辑 revision 与 submitted revision；成功只确认已提交版本。期间有新输入则保持 dirty 并排队下一次保存。恢复缓存按 revision 清理。测试延迟响应、连续编辑、保存失败和离开提醒。

同时，恢复缓存只保存 sheet.innerHTML，head 内 typo-custom 排版配置不在缓存中；离线排版变更需要一并恢复。

### 2. 测试脚本能破坏真实存档

位置：test.sh:11–18。真实配置和三个业务 JSON 被暂时移走；退出 trap 删除整个 pdfs/archive。锁只约束测试脚本，不保护正在运行的工作台或用户编辑。部分准备动作还发生在 trap 注册之前。

实际页面：现有投递的存档链接返回 archive not found。无法仅凭此认定就是测试脚本造成，但删除目录的代码路径确定存在。

建议：独立数据根、独立端口、虚拟配置和生成的测试夹具；不再对用户数据执行 stash/restore。恢复历史缺失 PDF 时，不能用今天生成的文件冒充当时的投递存档。

### 3. 投递 HTML 与 PDF 可来自不同版本

位置：server.mjs:753–778。新增投递复制最新 HTML，却直接复制现存 PDF，不检查是否过期，也允许没有 PDF 时成功建立投递。

隔离实测：HTML 为 NEW CONTENT B，存档仍是 OLD PDF A。

建议：从冻结内容生成 PDF，将文档版本、内容哈希、PDF 和存档状态绑定；生成失败明确提示，不能表现为完整存档。投递引用快照应免受普通历史配额清理。修改投递 docId 也不能改变原始投递归属。

### 4. PDF 重生成失败被报为成功

位置：server.mjs:1223–1252。/export 忽略 render 返回值，只检查旧 PDF 是否还存在，随后显示已重新生成。

隔离实测：渲染器强制失败，旧 PDF 存在，页面仍包含“已为你重新生成”。

建议：生成到临时文件、成功后原子替换；返回生成失败和旧文件的真实版本。/pdf 直链也应明确最新与存档语义。保存正文和生成 PDF 分离，避免每次自动保存启动渲染进程并延长保存等待。

### 5. 备份恢复的“合并”语义不完整

位置：server.mjs:1127–1150。文档目录合并复制，但 applications.json、materials.json 和 docs-meta.json 整份覆盖。预览只显示数量，不列冲突及本地独有记录。

隔离实测：恢复后只剩 backup-only，原 local-only 记录从活动数据中消失；恢复前安全副本存在，故不是不可恢复的物理删除。

建议：明确提供合并/替换语义，按 ID 显示冲突、保留本地独有项，提供可操作的回退入口。备份上传受统一 10MB 限制，而备份本身没有相同大小限制；需要保证自己生成的备份能够恢复。解包前校验条目类型、路径、总大小及结构，避免仅检查 docs 目录存在。

## P1：完善日常流程

### 6. 统计口径与提醒

server.mjs:1177 仍按当前“面试中/offer”计算面试转化；面试后拒绝会漏计。“状态漏斗”实际为状态分布。首页只提示前后有限时间窗口，逾期超过一天的事项会消失。

改为阶段事件历史、明确的曾进入面试口径及持续的逾期待办；旧数据不伪造历史。记录面试安排和完成状态，避免把预约等同于完成。

### 7. 正文提取、AI 上下文与定位

版本对比实际显示 {{NAME}}、已保存、保存、导出 PDF、历史。diff.mjs:2 的提取针对整份 HTML；AI review/match/chat 同样从整份落盘 HTML 提取文本，还可能包含隐藏章节。

建立统一正文提取：只处理文档内容、解码文本实体、排除工具栏及按任务规则排除隐藏内容；版本比较明确是否包括隐藏章节和排版变化。

AI 当前读取磁盘版，不一定是用户正在编辑的最新版本。提交 AI 请求时携带明确内容版本或先确保保存完成；返回建议绑定章节/文本范围和版本。findAndReplace 只找第一个单文本节点匹配，跨加粗节点会失败，重复文本可能改错位置。优先解决可靠定位，之后再增加更多改写预设。

### 8. 岗位版本入口

仍在 AI 匹配成功返回报告后创建按钮。直接提供“从这份简历创建岗位版”，不依赖模型可用。公司/岗位/JD 用统一表单，连接版本编辑、检查、导出和投递记录。

### 9. 投递与面试

看板已有可见横向滚动条，但新增大表单仍占首屏，最右列需滚动。增加收起的新增入口、待投递状态和清楚的卡片标题。表格已有搜索、渠道筛选，应保留复用。

面试详情主要支持新增，无独立编辑/改期/取消入口。当前记录还含 rollback @e11 等疑似测试数据；需核实并经确认后清理，不能凭关键词删除。

### 10. 编辑器操作完成度

值得保留：三栏、可折叠面板、章节目录、排版、素材插入、选区改写。

建议：首次打开自动适应宽度；保留用户选择的缩放；排版滑杆旁加数值输入及步进；全局撤销重做覆盖章节、排版、素材和 AI 编辑，避免只提供短时 Toast 撤销。

源码问题：章节导航按钮嵌套按钮，role=listitem 替换语义；新增章节未重新加入 IntersectionObserver；每次输入重建导航可能丢失焦点。素材对话框有 aria-modal，但需验证焦点限制与归还。公共页面未发现 viewport meta，窄屏 CSS 不等于真实移动端已适配。

状态问题：页数参考线最多 3 页，底栏却显示确定总页数；应使用估算标签或去掉固定上限，并以实际导出页数为准。减少动效模式禁了 transition，却未禁预览时 JS 设置的 rotateX，仍会出现瞬时倾斜。

## 可以精简或暂缓

1. 保留轻量卡片动效；暂停新增复杂 3D、粒子、场景引擎。动效收益应由实际使用决定。
2. 多模型配置保留在高级设置，主流程显示可用性，不占首页主要空间；“配置存在”不能宣称连通可用。
3. “量化增强”“突出贡献”“补充证据”等使用一个上下文工具入口，避免同级按钮重复，但保留有区别的任务能力。
4. 当前记录少且疑似测试数据较多，复盘收进投递页面次级入口，修正口径后再增加图表。
5. 文档少时压缩最近编辑和完整列表的重复内容；“PDF 就绪 2/2”与“2 份需更新”需要统一口径。
6. 精简实现中的重复 /snapshots 路由（后一个被前一个遮蔽）、过期文案、重复设计变量和 prompt 式编辑交互。
7. 暂缓全文翻译、模板商城、多人协作、自动投递、双向素材同步；除非明确的高频需求出现。

这些是建议精简入口或延后建设，不代表立即删除已有用户数据或功能。

## 值得新增的少量能力

1. 岗位工作包：JD、目标版本、建议、PDF、投递入口放在同一上下文。
2. 项目级积木：添加/复制/排序/隐藏单个项目经历，而不仅是整章；更贴近岗位定制。
3. 统一撤销、恢复与操作历史：包括文字、排版、素材和 AI 操作。
4. 导出命名规则及隐私副本：姓名/岗位/公司/日期，分享版可隐藏联系方式。
5. 一页/两页排版预设：展示具体改动并允许撤销，不以极小字号强行压页。
6. Cmd/Ctrl+K 快速操作：在已有操作稳定后提供搜索与跳转，不提前搭建复杂命令系统。
7. 手动启动的本地运行检查：AI 配置完整性、PDF 依赖、备份状态及最后失败原因；网络连通检测单独触发。

## 工程维护方向

当前原生 Node + HTML/JS 对个人工具仍够用。无需仅为 UI 迁移 React，也不必立即更换数据库。

针对问题抽取：保存与版本模块、PDF 任务模块、业务数据读写、统一正文提取、共享组件样式。server.mjs 约 1300 行及编辑器大文件中的职责应逐步分开，但不做无关全量重构。

当前 JSON 读取失败多处返回空集合，后续保存可能用空集合覆盖损坏数据；应区分不存在和损坏，损坏时停止写入并提示恢复。

本地监听不能替代请求来源约束。当前未看到统一写请求 Origin/Host 检查；建议补同源写保护、字段校验和输出上下文转义，备份导入只接受预期文件。无需为此引入多人账号体系。

Chromium 渲染路径固定到特定缓存版本；加入可配置路径与启动检查。导出中同步执行 pdfinfo/pdftotext 会阻塞 Node 请求处理，可将检查移入异步任务并缓存同版本结果。

## 建议迭代顺序

第一轮：保存 revision、测试隔离、存档一致性、导出失败、恢复冲突。
第二轮：正文提取、AI 版本与定位、直接岗位版本入口、项目级编辑与撤销。
第三轮：按用户真实使用情况选择投递面试强化或编辑效率强化，再整理公共组件和轻动效。

验收以用户操作结果为准：新版内容不会误标已保存；投递 PDF 对应冻结版本；恢复前可知影响；AI 修改落在正确位置；完成岗位版到导出的步骤减少。
