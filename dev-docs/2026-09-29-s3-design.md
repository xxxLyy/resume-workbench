# S3 设计：区域绑定与区域级分析

> 日期：2026-09-29 ｜ 版本：**v1.1** ｜ 状态：**已落地（2026-09-29，commits `d7838f8`..`c03489d`，13 个实现提交）；§2.1/§3.2 为落地修正版**
> v1.1 落地修正（实现与设计文档的口径差，已回写正文，不改变用户已定决策实质）：① 四个端点的文档 id 一律走 URL `?id=` 查询串（沿用 `/save`/`/job/changes` 既有约束），不以 body `doc` 字段传递；② `/zones` 不做正文 zid 存在性校验（孤儿 zid 由 `/save` zoneSync 单向同步兜底，meta 回写本身零正文副作用），`zoneRounds` 亦经 `/zones` 落盘；③ 未保存阶段 zid 为**确定性内容哈希**（djb2）而非随机串——初绑 meta 两次加载不失配，随机串仅用于同内容重复消歧（§2.1 修正）；④ `/ai/zone-rewrite` 的 locked 段落由服务端从 meta 派生，客户端不传 `lockedZids[]`；⑤ 追问文本经 body `extra` 可选字段拼进 analyze 的 user prompt（服务端压单行 + 截 200 字）。

> 上游：路线图 v4.1 S3（`dev-docs/2026-09-23-roadmap-magazine-and-features.md` §3.1）；决策 3（区域绑定是内容模型一等公民）与决策 5（既有编辑方式只叠加不替换）；S2 交接（`dev-docs/handoff.md` §6 撤销边界与注入纪律）。
> 用户已定（本会话三问）：① 锚点形状 = **段落稳定 ID 落盘（`data-zid`）+ docs-meta 存区域归属**（决策 3 的"非视觉标识"路线，否决纯外部映射——指纹在拆分/复制后漂移，无法强保证验收硬条款）；② 打点范围 = **全量段落单位打点**（单一不变量"每个段落单位恒有 zid"）；③ 面板落位 = **右栏新增「区域」Tab**（复用现有 Tab 机制，零布局重构）。

## 1. 目标与不做

目标（路线图 S3 原文七件事）：绑定模型（8 类语义区域，自动初绑 + 手动改绑，存 `docs-meta.json`）；区域列表面板（优先级/对话轮次/定位跳转）；区域级 AI 分析（结构化意见，请求只带该区域正文 + 全文摘要）；修改模式（输入即修改意见，针对单区域定向改写，走统一撤销栈）；预览着色仅编辑器可见；事实与表达分离（素材库升级 + `materials.json` 迁移）；段级保留标记（S3 承载，S4a 消费）。

不做：
- 不做区域级权限/多人（路线图原文）。
- 不重写 AI 面板与审阅面板（决策 5：只叠加；AI Tab 保留原文级功能）。
- 不做改写的并行多候选对比（S4a 的三段源对比）。
- 语音输入（S7a）不在本轮；修改模式输入框是普通文本框。
- 不动投递 PDF 样式与渲染链路；**不改 `template.html`**（S2 纪律延续：注入层 + `/save` 归一 + `extract.mjs` 标记三通道，新旧文档同权）。
- 不重写撤销逻辑（兼容式接入 §6.1 撤销语义）。

## 2. 数据模型

### 2.1 正文侧：`data-zid`

- **打点单位**（复用 `extract.mjs` 已有结构识别）：`p` / `li` / `h1–h4` / `.entry-head` / `.contact`。`section-title` 与 `section` 本身不打（章节身份由结构承载，不进绑定模型）。
- **格式**：`z` + 8 位 hex（如 `z3f9a1c2`）；生成即唯一，不回收复用。未保存阶段为**确定性内容哈希**（djb2，v1.1 修正）——两次加载生成相同 zid，初绑 meta 不失配；随机串仅用于同内容重复（粘贴克隆/同文段落）消歧。
- **不变量**：每个段落单位恒有 `data-zid`。编辑器在新建段落、拆分、粘贴时即时补 ID；服务端 `/save` 归一化发现缺失 zid 的段落单位时静默补齐（第二道防线，与 `ed-*-hidden` 同模式）。
- **双防线**：`extract.mjs` 新增 zid 解析（正文提取不受影响，AI 请求可按 zid 取段）；`/save` 归一保留 `data-zid` 属性不剥离。快照/存档/PDF 渲染零影响——属性无视觉语义，CSS 不引用它。
- **"不污染正文 HTML"的口径**（决策 3 张力的裁决）：不污染 = 不影响可见布局、渲染语义与独立渲染能力；非视觉属性属于决策 3 原文的"非视觉标识"合法路线。这是本设计对决策 3 的解读，已获用户确认（三问之①）。

### 2.2 meta 侧：`docs-meta.json` 新增 `zones`

```json
"linghaoxiang": {
  "zones": {
    "z3f9a1c2": { "zone": "work", "status": "confirmed", "locked": false },
    "z8b2d4e6": { "zone": "project", "status": "pending" }
  },
  "zoneOrder": ["personal", "work", "project", "skill", "education", "award", "summary", "other"],
  "zoneRounds": { "work": 4, "project": 1 }
}
```

- `zone`：8 类固定枚举 `personal / education / work / project / skill / award / summary / other`（自评 = summary）。
- `status`：`pending`（初绑猜测/继承，不静默生效）→ `confirmed`（用户确认或手动绑定）。stale 段落**直接清理**（用户已确认：靠快照回滚兜底，不做缓冲版本）——清理只发生在 `/save` 同步时。
- `locked`：段级保留标记（路线图⑦），S3 只承载与展示，S4a 消费。
- `zoneRounds`：区域级对话轮次（对话是区域维度，存 zid 级会在改绑时错位）。
- `zoneOrder`：用户可调的区域优先级（区域列表排序），默认顺序如上。
- **同步规则**：以正文 zid 为准——`/save` 时 meta 里正文不存在的 zid 清理；正文出现而 meta 缺失的 zid 补 `pending` + 启发式猜测。

### 2.3 素材库：`materials.json` 事实层

```json
{ "id": "m1", "title": "推荐系统重构",
  "facts": {
    "company": "", "role": "", "dates": "",
    "education": "", "metrics": "推理延迟 P99 从 800ms 降到 210ms",
    "contribution": "个人主导数据管道重设计",
    "conditions": "", "source": "绩效评定 2024H2"
  },
  "factStatus": "pending",
  "brief": "…", "technical": "…", "interview": "…",
  "attach": [], "tags": [], "createdAt": "", "updatedAt": "" }
```

- 事实层字段即路线图枚举（公司/职位/日期/学历/成果指标/个人贡献/条件/来源），**自由文本，不逐句结构化**（用户已确认）。
- `factStatus`：`pending / confirmed / outdated`；旧数据迁移：现有字段全部归入表达层（不动），`facts` 置空 + `factStatus: pending`。
- 现有 `confirmed` 布尔（岗位 prompt 只带已确认素材，`server.mjs:921`）迁移为 `factStatus === 'confirmed'` 语义。
- 事实层确认制与绑定确认制同口径：未确认不进 AI 请求。

## 3. 组件与数据流

### 3.1 新文件

| 文件 | 职责 |
|---|---|
| `zone.mjs` | 服务端纯函数（**启发式单一来源**）：初绑启发式（章节标题关键词 → 8 类）、meta zones 与正文 zid 的同步、按区域提取文本（喂 AI 的唯一出口）、区域分析/改写的 prompt 构建 + 受约束解析（沿用 `job.mjs` 模式） |
| `zone-panel.js` | 右栏「区域」Tab 注入层 UI（列表/意见卡/修改模式/改绑弹窗），`ZONE-INJECT` 注释对 + `data-zone-panel` 样式块，serve 注入即生效 |

改动文件：`extract.mjs`（zid 解析 + 按区域提取）、`server.mjs`（端点 + `/save` 归一扩展 + 注入）、`editor-shell.js`（Tab 机制 + zid 补点 + 着色）、`migrate-meta.mjs`（素材事实层迁移）。**不碰 `template.html`**。

### 3.2 服务端端点

- `POST /zones?id=` `{zones, zoneOrder?, zoneRounds?}` — 确认/改绑/调序/锁定/轮次的回写；条目校验 zid 格式 + zone/status 枚举（v1.1：不做正文 zid 存在性校验，孤儿由 `/save` zoneSync 兜底）。
- `POST /zones/init?id=` `{entries: [{zid, sectionTitle}]}` — 初绑：客户端补完 zid 后上送段落（启发式只吃章节标题）；服务端跑启发式（`zone.mjs` 单一来源）分配 zone（全 `pending`）落 meta 并返回写入后值；已有 zones 幂等不动。避免启发式在注入层重复实现（DRY）。
- `POST /ai/zone-analyze?id=` `{zone, extra?}` — 请求体只带该区域段落文本 + 全文摘要（章节标题 + 每章首行截断，复用 `extract.mjs`）；`extra` 为 chips 追问文本（可选，压单行截 200 字）；返回受约束 JSON `{echoes[], reminder, suggestion, chips[]}`。
- `POST /ai/zone-rewrite?id=` `{zone, instruction}` — 返回该区域内逐段候选 `[{zid, original, candidate}]`；`locked` 段落由服务端从 meta 派生（v1.1：客户端不传 `lockedZids[]`），跳过并在结果 `skipped[]` 标注。解析失败/事实护栏（复用 `job.mjs` 的数字/日期检查）→ conflict，不落正文。
- 无模型时（config 缺失）：区域 Tab 显示明确降级提示，绑定/确认/锁定功能不受影响（不依赖 AI）。
- **初绑触发（客户端，v1.0 自审修正）**：`editor-shell.js` 加载时检测 meta 无 `zones`（`GET /edit` 页面数据已带 `hasZones` 标记，GET 保持零写副作用）→ 注入层遍历正文补 zid → `POST /zones/init` 上送段落数据 → 服务端启发式分配（全 `pending`）落 meta → 客户端渲染区域列表。**zid 生成点必须单一 = 编辑器注入层**（服务端在正文无 zid 时无法生成与客户端一致的 ID），**启发式单一来源 = `zone.mjs`**（经 `/zones/init` 调用，注入层不重复实现）；用户打开即见区域列表（异步数百 ms），确认前不生效，zid 随下次 `/save` 落盘。

### 3.3 前端数据流

```
区域Tab                    服务端                     落点
───────                    ────                      ────
点区域 → 定位滚动+闪烁      —                         CSS.highlights（不落盘）
点「分析」 ──────────────→ /ai/zone-analyze → 意见卡（右栏）
点 chip 追问 ────────────→ 同上（轮次+1，存 meta）
输入修改意见 ────────────→ /ai/zone-rewrite → 右栏 diff 预览
点「接受」 → __edPushUndo('区域改写') → 按 zid 替换 DOM
         → __edMarkProgrammatic() → undoToast
改绑/确认/锁定 ──────────→ POST /zones → docs-meta.json
```

- **着色**：区域 Tab 顶部 toggle，开 = 每区域一个 `Highlight`（该区域所有段落 Range `.add()`），`::highlight(zone-work)` 8 色淡背景；仅编辑器运行时，关闭即消失，任何情况不进落盘 HTML（handoff §6 纪律原文照做：临时视觉效果一律走 CSS Custom Highlight API，不给正文节点挂 class）。
- **待绑定提示**：区域列表头部一行「待绑定 N 个段落」，点击进入逐段确认流（定位 → 弹窗选 8 类）。

### 3.4 zid 生命周期（关键边界）

| 操作 | 语义 |
|---|---|
| 新建段落 / Enter 拆分 | 新段新 zid；拆分时新段**继承原 zone 为 pending** |
| 退格合并 | 前段 zid 保留，后段 zid 消失 → 下次 `/save` 清理 |
| **粘贴 / 条目复制** | **克隆节点全部重打新 zid**（用户已确认：保唯一性），meta 侧继承原 zone 为 pending |
| 排序 / 隐藏 | zid 随节点走，零处理 |
| 程序化撤销 | 恢复旧 innerHTML，zid 原样回来；meta 未被 `/save` 清理故天然对上 |
| 快照回滚 | 旧 HTML 回来，下次 `/save` 时 meta 同步（多余 zone 清、缺的补 pending） |

唯一性维护责任：编辑器（paste/clone 必重打）+ `/save` 归一（发现重复 zid 保留首个、其余重打）双保险。

## 4. 错误与边界

| 场景 | 行为 |
|---|---|
| meta zones 与正文 zid 不一致（任何来源） | `/save` 归一单向同步：正文为准；重复 zid 保首重打；同步时不改 zone 归属 |
| AI 解析失败 / 返回非法 JSON | 重试 0 次，右栏显示「分析失败，稍后再试」，正文零接触 |
| 事实护栏触发（改写引入新数字/丢日期） | 候选标记 conflict，禁用接受按钮，展示原因 |
| 改写落点失败（zid 在预览期间被用户编辑删除） | 接受时校验 zid 存在，不存在 → Toast「段落已变化，请重新生成」，不入撤销栈 |
| config 无模型 | 绑定/确认/锁定/着色全可用，分析与改写按钮置灰 + 降级说明 |
| 投递冻结 / 快照 / 存档 PDF | zid 属性无 CSS 引用，渲染链路无感知，零回归风险 |
| 未确认（pending）绑定 | 不阻止任何编辑、导出、AI 面板既有功能；仅区域分析把 pending 段落计入区域文本 |

## 5. 验收（路线图原文 + 本设计细化）

- 绑定持久化且刷新保留；旧文档迁移后自动初绑可用。
- 区域改写落点正确（按 zid 定位，复用跨文本节点匹配）。
- **段落拆分/合并/复制/排序/撤销/回滚后绑定仍正确**（§3.4 全表为验收依据）。
- 未确认绑定不阻止手动编辑与普通导出。
- 快照/存档渲染不受着色与 zid 影响（保存后落盘 HTML 无 zone class、PDF 像素等价沿用 S2 门禁）。
- 直接编辑/章节积木/选区改写零回归（决策 5）；S2 全部 194 断言零回归。
- 素材旧数据迁移幂等；事实层确认前不进 AI 请求。

## 6. 任务切分（供 plan 细化）

```
① 数据层（zid 规范 + /save 归一 + extract 解析 + 初绑启发式 + 素材迁移）
② 区域 Tab 列表 + 定位 + 着色（纯 UI，无 AI）
③ /zones 回写 + 改绑弹窗 + 待绑定队列
④ 区域级分析（stub 先行）
⑤ 修改模式 + 撤销接入
⑥ 素材事实层 UI（/materials 页，可并行推进，无正文依赖）
```

①→②→③ 强依赖；④⑤依赖①②；⑥独立。每步可独立验收，中途停下产品仍可用。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 自动初绑错绑（路线图已识别） | 初绑结果全部 `pending` 不静默生效；与素材确认制同口径 |
| zid 唯一性被绕过（第三方编辑 HTML、极端粘贴路径） | `/save` 归一重打兜底 + 浏览器级测试覆盖 paste/clone |
| 区域 AI 请求意外携带全文（隐私/成本） | 提取出口唯一（`zone.mjs`），结构测试断言请求体只含该区域 + 摘要 |
| 撤销语义与 S2 边界冲突 | 区域改写严格走 `__edPushUndo → 变更 → __edMarkProgrammatic → undoToast(opId)` 既有链路，不新增栈语义 |
