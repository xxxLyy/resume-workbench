# 可靠性修复 + 岗位草稿主流程（A–E 轮）

日期：2026-09-17 ｜ 范围：保存一致性 / 测试隔离 / PDF 与投递版本 / 备份恢复 / 正文提取 / 岗位草稿与审阅 / 两页导出 / UI 细节。

## 一句话结论

`test.sh` 已重写为**全隔离**（独立数据根 + 独立端口 + 虚拟配置 + 假渲染器 + 本地假 LLM，测试前后对真实数据做指纹比对），**112 个断言守卫 + 25 项 Playwright 浏览器级断言全绿**；真实文档已迁移 v5 编辑器并快照留档；真实模型未调用（AI 路径均为模拟验证）。

## 一、修了什么（对应 2026-09-14 审计）

### P0-1 保存期间输入被误判已保存
- `template.html` 保存状态机重写：**编辑修订 / 已提交修订 / 已确认修订**三态分离；请求成功只确认它实际提交的修订。
- 保存期间的新编辑保持 dirty，完成后 600ms 续存；请求期间再次触发保存会排队（`queued`）。
- 本地恢复缓存改为 `{v:2, rev, body, typo}`：**正文与排版一起缓存**，按修订清理（只清 ≤ 已确认修订）。
- 新增多标签冲突检测：`/save?baseMtime=` 与磁盘 mtime 比对，落后即 409；前端出现冲突条（以我的为准覆盖 / 加载服务器版本 / 继续编辑），不静默覆盖。
- 正文保存与 PDF 生成分离：`/save` 不再渲染；新增 `POST /render`；导出页按需渲染。
- 证据：`test.sh` 第 2/3/4 节 + `test-editor.mjs` 用例 1（保存 A 期间编辑 B → B 保持未保存、缓存未清、排队后两者都落盘）。

### P0-2 测试脚本能破坏真实存档
- `server.mjs` 支持 `RESUME_ROOT` 数据根（代码/静态资源仍来自 APP_ROOT）；`test.sh` 全量重写：`mktemp` 独立目录、端口 17899、虚拟 config 指向本地 stub LLM、夹具由 `/new` 与模板生成、假渲染器控制文件切换失败。
- 不再 stash/restore 真实 JSON，不再删除 `pdfs/archive`；退出 trap 只清理临时目录。
- 每次运行首尾比对真实 `docs/*.html + 三个 JSON` 指纹，任何写入即失败。
- 疑似测试记录只出调查清单：`dev-docs/2026-09-17-suspect-test-records.md`（不自动删除）。

### P0-3 投递 HTML 与 PDF 可来自不同版本
- `/app/add` 改为：先冻结当时内容到 `snapshots/{docId}/{ts}.html`，记录 `contentHash`，**从冻结内容**渲染存档 PDF（`render.mjs --src/--out`）。
- 渲染失败仍记录投递，但 `archive.status='failed'`，详情页明确显示「存档 PDF 缺失」并提供「从快照重新生成」；**不允许用当前文档冒充当时版本**。
- 投递引用的快照受保护：配额清理跳过 `snapTs` 与基准快照（测试：塞 55 个快照后引用快照仍在，配额仍生效）。
- 改稿不影响已有存档（测试断言 md5 不变）。

### P0-4 PDF 重生成失败被报为成功
- `/export` 先渲染并记录成败：失败时显示 `❌ 重新生成失败 + 原因`、旧 PDF 标注「生成于 X，不是最新内容」，不再出现「已为你重新生成」。
- `render.mjs` 改为**临时文件 + 成功才原子替换**，产物 <1KB 视为失败；Chromium 路径支持 `RESUME_CHROMIUM`。
- 语义分离：最新版（`/pdf`，文件名 `姓名_岗位_公司_日期.pdf`）、历史导出（新增 `/snapshot/pdf?id=&ts=` 从快照渲染）、投递存档（`/archive-pdf`，缺失给 404 说明）。

### P0-5 备份恢复「合并」语义不完整
- 恢复升级：预览逐条列出文档 新增/冲突/本地保留、投递与素材 新增/冲突/保留（设置页可视化）。
- 默认 **merge**：本地独有保留，同 id 冲突以备份为准（预览中明示）；可选 **replace**。
- 每次恢复前生成回退点 `backups/restore-<ts>/`（含 manifest），设置页提供「↩ 回退这次恢复」。
- 上传上限从 10MB 提升到 300MB 且流式落盘 → 自产备份一定能恢复（测试：下载自产备份 → 预览 → 合并恢复）。
- 校验 tar 条目：拒绝绝对路径/`..`/非预期前缀（测试：`../pwned` 包 400）。
- JSON 损坏停写：读损坏 → 标记并在页面横幅提示；写损坏文件 → 500 且不覆盖（测试覆盖）；恢复前校验备份内 JSON。

### P1 正文提取 / AI 版本 / 定位
- 新增 `extract.mjs` 唯一出口：排除 `edit-toolbar/page-line/toast/注入外壳/脚本/样式/占位符`；隐藏章节与条目默认不参与（`hidden=1` 可显式包含）；实体解码。
- AI review/match/chat/prep、diff、导出检查、restructure 全部走统一提取（版本对比页标注隐藏口径）。
- AI 请求前客户端先 `flushSave()` 并携带 `baseMtime`；磁盘有更新未同步时服务端 409，客户端提示重试。
- 替换算法升级（ai-panel 与 job-panel 同算法）：**跨文本节点**匹配（加粗/分段不再失败）、按出现序号 + 上下文消歧重复文本；应用前找不到原文即拒绝并提示。
- RGA 根因修复：`removeElements` 内层扫描正则未处理闭合斜杠导致"整段吞掉"（首版实现时被本测试当场抓住）。

### 岗位草稿主流程（新增）
- 入口：首页「🎯 针对岗位生成简历」（公司/岗位/JD 链接/JD 文本/母版选择）与编辑器顶栏「＋ 岗位草稿」（模态、焦点圈定、aria-modal）。
- 创建即独立文档：`meta.job{status, sourceSnap, sourceHash, materials, changes, todos}`；**不依赖模型成功**；快照冻结来源版本；同 parent+company+role 重复创建返回 409 + 已有 id。
- 素材确认制：新增素材默认「待确认」，旧素材不会自动确认；素材库支持逐条/批量确认；生成 prompt 只带**已确认**素材（测试断言未确认素材不出现）。
- 生成建议：`job.mjs` 约束 prompt + 受约束 op 解析；模型不可用/输出坏 → 409/502，草稿与母版不受影响；重试产生新候选（旧 pending 标记 superseded），不覆盖已接受/已撤销历史。
- 确定性事实护栏（`factGuard`）：改写引入原文没有的数字、丢失原文日期、新增内容含数字 → **强制 level=conflict**，导出前必须人工处理。
- 审阅面板 `job-panel.js`（右栏默认 Tab）：分组 = 普通表达（批量接受）/ 排序调整（批量接受）/ 隐藏经历（逐条确认）/ 可能改变原意（单独审阅）/ 事实冲突（阻断导出）/ 已处理历史；每项含理由、来源、前后文、定位、接受/撤销；待补充信息独立面板（不进正文）。
- 状态持久化在 docs-meta.json，刷新后保留；接受/撤销操作进入统一撤销栈（状态栏「↩ 撤销」按钮，覆盖章节/条目/素材/AI/审阅的程序化修改）。
- 导出门控：冲突 pending → 下载与「记录已投递」禁用并列明；重点审阅仅提示不阻断；成功后自动标记「可投递」，**改稿使可投递失效**（不已有投递存档）。

### 两页与导出
- 编辑态页数改为**无上限估算**并标注「估算，以导出为准」；底部状态「约 N 页」。
- 导出页展示实际页数/空白页/孤立标题/文本层字符检查；>2 页时给出可读处理建议（去重/压缩长要点/项目数），明确不靠小字号硬塞。
- 导出前自动保存（编辑器点导出时先 flush）。
- 记录已投递：绑定当时冻结快照 + 存档 PDF + 内容哈希；不自动发送、不自动计入已投递。

### UI / 无障碍 / 其他
- 章节导航去掉嵌套按钮（div[role=listitem] + button），新增条目级 ↑↓👁（项目级积木）；输入时不再重建导航丢焦点；新增章节会重新纳入 IntersectionObserver。
- 排版滑杆加数值输入；缩放支持数值输入；预览的 rotateX 尊重 `prefers-reduced-motion`。
- 首页精简：删掉与完整列表重复的「最近编辑」，改为「继续处理岗位草稿」；投递新增表单折叠；逾期提醒不再 24h 后消失；PDF 口径统一为「PDF 同步 / PDF 较旧 / PDF 未生成」。
- 全站补 `<meta name="viewport">`；`/pdf`、历史 PDF、存档 PDF 命名与语义分别明确。
- 修复真实环境回归：首页文档卡因 `docInfo(文件名)` 误传导致列表为空（真实服务验证时抓到并修复）。

- `RESUME_ROOT` 缺省 = 项目目录，常驻服务行为不变；新增目录 `backups/`（回退点）、`pdfs/history/`（历史版本渲染缓存）。
