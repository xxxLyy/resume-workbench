# S2 应用层全量换肤（杂志编辑感）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把简历工作台的应用界面（首页/看板/复盘/设置/编辑器外壳/两个面板）换成统一的杂志编辑感视觉，并补齐五项基础编辑能力与撤销边界，同时保证简历正文样式、冻结件字节与投递 PDF 零变化。

**Architecture:** 两层设计 token——应用页面走 `server.mjs:page()` 的 `/*A-VARS*/:root`，编辑器与面板走 `editor-shell.js` 运行时注入的 `body.ed-on{--ed-*}`（整块包在 `@media screen`、保存时按 `data-ed-shell`/`data-ai-panel`/`data-job-panel` 属性剥离）。既有文档的内联主题块**一律不动**：编辑器观感统一由注入层用更高特异性选择器覆盖实现，因此不存在任何 serve 端文档变换，冻结件字节与 `styleHash`/`renderInputId` 不漂移。新编辑能力一律走既有 `window.__edPushUndo(label)` → 变更 → `notifyEdit()` 模式；格式化操作例外（走浏览器原生撤销，见 Task 5 决策）。

**Tech Stack:** Node.js ESM 零依赖单文件服务器（`server.mjs`）、浏览器端 ES5 风格 vanilla JS（`editor-shell.js` / `ai-panel.js` / `job-panel.js` / `template.html`）、bash + node heredoc 测试套件（`test.sh` / `test-structure.sh` / `test-render.sh` / `test-editor.mjs`）、playwright-core 1.60.0 + `chromium.mjs` 解析器、`tools/pixel-diff.mjs`（pdftoppm + ffmpeg rgb24）。

**Spec:** `dev-docs/2026-09-26-s2-design.md`（v2.1：含用户 4 处修正、3 项计划级调整，以及编制本计划时的两处落地修正）；上游 `dev-docs/2026-09-23-roadmap-magazine-and-features.md`（v4.1）S2 节与 `dev-docs/2026-09-23-m1-overall-plan.md` S2 节。

## Global Constraints

每条都适用于所有任务，任务内不再重复：

1. **铁律一（冻结件只用冻结字节）**：快照/存档/任何 `--src` 渲染只读冻结字节，绝不读当前 meta；`render.mjs` 保持 meta-blind。S2 不得新增任何"渲染时按当前样式重算"的路径。
2. **禁止 serve 端文档变换**：`GET /edit`、`GET /pdf`、`/export` 等任何链路都不得删改文档自带的 `<style data-theme>` / 内联样式块。理由：`/save` 上送浏览器整页 HTML（`template.html:229-248` clone → `server.mjs:874-882` 剥离注入块），serve 阶段删掉的样式会在下一次保存时永久消失。
3. **`themes/` 零改动**：S2 全程 `git diff --stat <base> -- themes/` 必须为空（含 `themes/resume-classic.css:63-111` 的编辑器外壳段与 `:111` 的 `@media print` 隐藏行，一律保留原样）。
4. **数据契约不变**：`docs-meta.json` 不新增存储字段；路由集合不变；既有 API 请求/响应形状不变；`schemaVersion` 与 `data-editor`（v5）不动。
5. **简历正文不受影响**：`.sheet` 内文字的颜色/字体/字号/行高/间距由文档主题 + `meta.typo` 决定；注入层只允许改编辑器指针色（`caret-color`）与悬停虚线提示色（`outline-color`），禁止改任何正文文字样式。
6. **无新依赖**：不得新增 npm 依赖；playwright-core 保持 1.60.0；`editor-shell.js`/`template.html` 内新增代码一律 `var`/`function`（ES5 风格，与现有文件一致）。
7. **验证纪律（v2.2 强化）**：`pipefail` 必须覆盖**整条**命令——管道要放进同一个 `bash -o pipefail -c '…'` 里，或先重定向到文件再查看并显式回显退出码。
   - 正确：`bash -o pipefail -c 'bash test-structure.sh 2>&1 | tail -30'`
   - 正确：`bash test-structure.sh > /tmp/x.log 2>&1; echo "exit=$?"; tail -30 /tmp/x.log`
   - **错误（禁用）**：`bash -o pipefail -c 'bash test-structure.sh' 2>&1 | tail -30` —— 外层管道不受 pipefail 保护，已实测内部退出 42 时整条命令仍返回 0。
   任何"通过"结论必须附实际命令、`exit=` 的数值与输出片段。
8. **隐私门禁**：每个任务提交前 `bash privacy-check.sh` 必须绿；测试与截图一律使用隔离 `RESUME_ROOT` 夹具（`测试候选人` 等假数据），**禁止**把真实 `docs/` 内容写进仓库或截图证据。
9. **不碰 launchd 服务**：测试全部自起自杀进程（`RESUME_ROOT` + 空闲 `PORT`）。重启 `com.lhx.resume-server`（:7766）只在 Task 7 且经用户明确同意后进行。
10. **提交风格**：沿用仓库现有风格 `S2-T<n> <中文摘要>`（如 `S1-8 状态维度/派生关联/导出不可变与并发幂等`）；文档提交用 `docs: …`。每任务一个提交（修复轮另起提交，不 amend）。
11. **瞬态状态不落盘（v2.2 改写）**：任何运行时新增的 DOM/class/样式必须挂 `data-ed-inj`（或经 `mount()` 落在 `<!--SHELL-INJECT-->` 注释对内），由 `server.mjs:875-882` 的注入块剥离 + `extract.mjs` 标记表兜底；**不得依赖 `template.html:230-232` 的客户端清理**（那是冻结模板里的旧文档自带逻辑）。会落到正文节点上的临时效果（高亮、定位提示）一律用 CSS Custom Highlight API 实现，不改 DOM。

**决策（逐条写进任务报告，评审会查）：**
1. **撤销语义唯一化（设计 §6.1）**：一次 ⌘Z 撤销"最近输入的 B"，A 与加粗保留。定向撤销只对程序化操作提供。格式化走 `document.execCommand`，**不压快照栈**。
2. **来源判定用计数器，不用布尔值**：`nativeInputCount` 只在 `e.isTrusted === true` 时 +1；每条 op 在完成时记录 `nativeCountAtApply`；⌘Z 仅当两者相等才消费栈顶。布尔版"最后一次来源"被否，因为面板改动走的是自己派发的合成事件（`ai-panel.js:160`、`job-panel.js:139/142`），布尔值会把它们误判为原生；计数器 + `isTrusted` 天然覆盖，且不需要外壳的 `syntheticInput` 标志（合成事件本来 `isTrusted === false`）。
3. **共享出口**：把面板里裸派发 `new Event('input')` 的两处改成调用 `window.__edMarkProgrammatic()`（行为等价，多了一个 op 时间戳），并给 `job-panel` 的隐藏/显示路径补上 `touch()`（实测这两处改完 DOM 不派发事件 → 既不标脏也不进撤销，属同族缺陷）。
4. **快照遇后续输入不得静默回退**：⌘Z 压根不消费；工具条/Toast 消费前若 `nativeInputCount > top.nativeCountAtApply` → `window.confirm` 显式告知"其后输入会一并回退"，取消即无操作。与 `#ed-addsec` 现有 `prompt()` 同风格，不新增弹窗抽象。
5. **Toast 绑 opId**：栈顶不是它 → 拒绝并把该 Toast 置为"已失效"（按钮禁用 + 文案），绝不弹别人的 op。修 `:805`+`:820` 的现存双重恢复缺陷。
6. **瞬态根因消除，不改 `template.html`**：`flashEl` 改用 CSS Custom Highlight API（零 DOM 变更，旧文档同样受益）；查找高亮同样走 Highlight API；聚焦模式用 `body.ed-focus` 但由 **服务端 `/save` 归一化**剥离（旧文档的内联清理选择器不认它）；`#ed-jobpop/#ed-jobmask` 等外壳节点本就在 `<!--SHELL-INJECT-->` 注释对内，服务端已剥离，再补进 `extract.mjs` 作第二道防线。
7. **查找替换按正文块建流**：允许跨 `<b>` 等行内节点，**禁止跨块级边界**（消除"上一段结尾+下一段开头"的虚假命中，也消除跨块 `deleteContents` 删除中间结构的可能）；内容一变即重算命中；替换前逐个二次校验目标文本，不符即中止。

## 附 B：留给 S3 及以后的整理项（本计划刻意不做）

1. **跨文本节点匹配算法三处并存**（`ai-panel.js:122-160`、`job-panel.js:109` 区、`editor-shell.js` 查找替换）→ S3 区域级改写需要同一原语时抽共享模块；注意 ai-panel 版本仍可产生跨块假命中（它按文本流整体匹配，但不删结构），合并时一并修掉。
2. **撤销栈无 redo、粒度为整片快照**；⌘Z 只在"该 op 之后无新输入"时消费，定向撤销依赖确认弹窗 → S3/S4 若需要 redo 或 op 级增量回退，再评估栈结构（S2 明确"不重写撤销逻辑"）。
3. **`execCommand` 弃用风险** → S2 仅四类格式动作使用；引入更多格式化能力时评估 `beforeinput` + Range。
4. **`#ed-addsec` 用阻塞 `prompt()`** → S2 只补了压栈，交互形态留给后续。
5. **Highlight API 依赖**（flash 与查找高亮）→ 若目标浏览器不支持，当前降级为"只滚动定位/只计数不高亮"；S7 若要支持外部浏览器需重新评估。
6. **`render.mjs` 端 print-sanitize 补充**：T2 Step 5b 实测既有文档全部自带 print 隐藏规则 ⇒ S2 不动渲染路径；仅当出现缺规则的冻结件（如外部导入 HTML）时再实现，并须重跑像素等价。
7. **对比度脚本化**：S2 是"token 定值时人工表 + 报告留档"，未做成常驻断言；S6 引入多配色时应脚本化进 `test-structure.sh`。
8. **面板宽度的真实调节**：实测只有折叠两态（`0px`/`208px`、`0px`/`320px`），无拖拽 → 若将来支持拖拽，`resume-ui:<docId>` 需新增数值字段并显式区分"折叠"与"宽度 0"。
