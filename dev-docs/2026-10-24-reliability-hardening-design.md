1. 在途新输入不能因应用候选、处理回执或回滚而丢失。

6. 不将未执行的必需验证报告为通过。

## 3. 区域建议的版本与应用协议

### 3.1 生成前置与请求身份

分析与改写均先使用现有保存 hook。必须检查返回值为成功，并确认 `__edIsDirty()` 为 false、已知磁盘版本有效。hook 缺失、返回 false、保存冲突或保存后仍 dirty 时停止本次请求；不静默降级为旧盘内容，也不无限循环保存。

在同一轮同步代码中捕获当前文档版本、区域及目标节点快照，然后发出请求。服务端校验文档存在、请求版本及区域合法性；响应携带生成基线。生成等待期间允许继续编辑。

面板维护递增请求身份，分析和改写共用当前活动请求身份。切区域、新请求、关闭/重建失效上下文均使旧身份失效。只有当前身份的响应可以修改结果、缓存、错误和 busy 状态。A→B→A 不能恢复旧 A 请求的有效性。

错误使用可区分的机器码：`LLM_NOT_CONFIGURED`、`STALE_DOCUMENT`、`RESOURCE_BUSY`、`DOC_NOT_FOUND`、`INVALID_REQUEST`、`NO_APPLICABLE_CANDIDATES`。409 不能统一解释成“未配置大模型”。

### 3.2 两种比较各司其职

- 浏览器捕获每个目标节点的 DOM 快照，用来检查生成后或提交在途是否发生了本地变化。比较应保留文字与内联结构；格式变化也视为用户修改，保守跳过。
- 服务端使用版本为 `zone-v1` 的区域基线字段，记录 `before`、其比较指纹和原 zone。区域专用比较适配器对 HTML 片段只解码一次实体，再折叠空白并 trim；对浏览器已解码文本不再解码。`A B` 与 `AB` 不相等。最终事务复核磁盘正文、提交前 HTML、zone 与 locked。
- 不直接把浏览器 `textContent` 与未解码的 HTML 文本比较。HTML 实体、空白、换行及内联标签必须有明确测试。
- 不为修区域比较而改变全局 `parasOf`、既有证据指纹或 PDF 渲染身份的含义。需要的新口径只用于本协议，显式标明版本。

### 3.3 扩展现有 JSON `/save`

在现有 `requestId / baseRev / html / ops` 协议上增加可选 `zoneOps`，用于普通母版和岗位草稿。旧请求没有此字段时行为不变。`zoneOps` 不与非空岗位 `ops` 混用，混用返回 400，避免两套操作互相改写锚点。

关键约定：**请求 html 是尚未套用任何候选的当前正文快照**。候选独立置于 zoneOps；不能先把全部候选写进 html，再让服务端声称只接受其中一部分。

每个区域操作字段固定为：`operationId`、`zid`、`baselineVersion='zone-v1'`、`before`、`beforeHash`、`zone`、`candidate`。before 为生成时的区域专用规范化文本，beforeHash 使用既有 `contentHash(before)`；candidate 为纯文本。相同 zid 重复操作、格式不合法或载荷结构错误属于整次 400，不当作可跳过业务项。候选仍执行已有事实护栏，不信任客户端提供的 level。

客户端在接受时先按生成时 DOM 快照剔除本地已变化候选，保存当前编辑并确认成功，再提交剩余候选、文档版本和当前快照。保存成功不会让原本已变化的候选重新有效。zoneOps 请求同时携带 `baseMtime`，绑定实际已确认保存的正文；用于取得 baseRev 的读取若对应别的 mtime，应停止，不以最新 rev 为旧 HTML 背书。服务端严格匹配正文 mtime 与 rev，不允许缺省版本绕过保护。服务端在现有文档/元数据提交临界区按以下顺序处理：

1. 验证请求形状与幂等身份；同 requestId、同请求内容的已成功提交只返回原回执，不写文件。同 ID 内容不同返回 400。
2. 版本冲突属于整次 409，正文、快照、meta、PDF 均不产生本次变更。
3. 对每个目标复核当前原文、提交快照原文、区域、锁定和事实护栏。检查与最终正文/meta 写入之间不得存在可被 `/zones` 更新穿过的窗口；`/zones`、`/zones/init` 等相关归属/锁定写入也须遵守同一文档互斥边界，不能只给保存侧加锁。锁顺序沿用既有事务规范，最终 meta 写入不得覆盖新锁。仅 pending→confirmed 而归属/锁未变不使候选失效。
4. 将目标分成安全和跳过两组。删除、原文变化、改绑、锁定或事实冲突逐段跳过，返回明确原因；安全目标应用到提交前快照，候选按纯文本安全写入，不能重新解释成 HTML。
5. 零安全目标返回 409 `NO_APPLICABLE_CANDIDATES`，携带跳过原因，不写正文/meta/快照、不登记成功回执。
6. 有安全目标时，复用现有注入剥离、归一化、快照和事务，一次提交整个安全子集，rev 只推进一次。响应包含 requestId、rev、mtime、applied、skipped 及实际应用的逐段 delta。

区域成功回执使用文档级 `zoneSaveReceipts` 环形记录，最多 50 条；普通母版不得为此伪造 `meta.job`。现有岗位 `job.saveReceipts` 保持原语义。回执记录与正文、meta 同事务提交，备份/恢复自动随现有 docs-meta 文件覆盖，不新增运行时数据文件。幂等保证限定在保留的回执窗口内；窗口外仍由版本冲突防止旧请求静默覆盖。

### 3.4 回执合并与撤销

客户端等待服务端回执后才把已确认 delta 合并进页面，不进行整页 HTML 替换。合并前逐段比较提交时捕获的 DOM 快照：

- 未变化且服务端确认应用的段落：更新候选。
- 请求在途期间又被本地修改的段落：保留本地输入，标记 dirty/待核对，说明磁盘已应用结果而页面存在后续编辑；后续保存继续遵守版本保护。
- 被服务端跳过的段落：不套候选。

仅为实际发生的本地 DOM 合并压入一条程序化撤销记录，快照在合并前捕获，保留此前在途输入；使用现有 `__edMarkProgrammatic` 和同一 opId 的 Toast。若没有可合并 delta，不制造空撤销记录。

回执不能把整页误标为 saved，不能清掉请求期间产生的编辑修订。请求失败或结果未知时保留本地原文与候选，不整片回滚、不自动重投。自动保存与本次提交相撞时以现有版本冲突为准，不用新读到的 rev 强行重放旧正文；显示冲突并保留本地缓存。

成功回执还须接入普通保存状态机：只接受匹配当前 requestId 的成功回执作为本次已知磁盘 mtime/rev，推进基线时保留未确认的编辑修订和本地缓存，不把整个当前 DOM 标记为已保存。若本地已知基线已经被另一次确认的保存推进，旧回执不得覆盖更新基线，应保留 dirty 并进入核对。后续自动/手动保存提交局部合并后的当前 DOM 及对应盘基线；第三方继续改文仍按原冲突保护拒绝。同请求重放原回执不能倒退已知版本。该衔接通过注入层适配，冻结模板保持不变。

## 4. 任务状态正确收敛

`finishGenTask` 的业务回调返回显式的成功/拒绝结果，所有调用点统一采用该契约。回调不得自行设置 `genTasks[kind].status` 后再依赖外层猜测。业务前置校验先于内容变更；拒绝结果不得夹带已经修改的内容、批次或版本，必要的内容 patch 仅在成功分支提交。

统一完成出口先检查 taskId 与 running、再检查时限，再执行业务校验；只有成功结果写 done。业务拒绝写 error 和具体原因，同时保持旧内容及其生成版本不变。

| 情况 | 最终行为 |
|---|---|
| 正常生成、前置条件仍成立 | 提交内容及版本，任务 done |
| 面试生成期间 evidenceGen 改变 | 不替换旧面试、不推进 interviewGen，任务 error |
| taskId 已被替代或任务已取消 | 丢弃迟到回调，不污染新任务 |
| 已超过任务期限 | 任务 error，内容不提交 |
| 模型调用或解析失败 | 保留旧结果，任务 error，可明确重试 |

现有同类任务及合计并发业务规则保留；资源包另约束实际请求，二者不能混同。

## 5. 来源可信与旧数据兼容

### 5.1 面试请求使用真源集合

用一个薄纯函数根据 evidence、paras 和既有 `refFresh` 解析本次来源。按有效 para ref 的 zid 重取正文，并核对 ref.hash；不使用展示 quote/title 兜底。

一行多个有效 para 沿用“第一个可用 para”，不拼成综合段落。保留原 evIndex；跳过行不重新编号。只有素材、失效来源或来源缺失的行不生成证据派生追问，返回按原因计数的说明。

提示词与解析器共用同一份请求来源集合。每段沿用最多 600 字的实际发送片段；引文只能在实际发送片段中匹配，不能用未发送部分替模型补证。该集合包含来源 zid、完整段落指纹和发送片段，仅在本次任务内存在。

仅素材的证据仍留在证据表；本轮不新增素材型面试追问。若没有可用 para，仍可产生明确无引文的 generic 作答思路；空输出不得假装成功。

### 5.2 引文、数字归属和程序来源字段

锚定链的每条非空引用必须命中所属来源片段。generic 非空引用同时提供 sourceZid，且必须来自本次请求来源集合；缺失、未知、跨段或伪引用要点丢弃并计数。沿用现有至少 6 字及空白归一规则。

generic 空引用允许保留为未经核验的作答思路，不授予原文依据标记。真实引用的数字护栏以所属段落为基准，不能借另一段相同数字洗白；无引文思路保留现有数字告警，但该告警不授予来源可信标记。

来源字段由程序产生：`source={type:'para',zid,hash}` 或 `{type:'none'}`。保留旧 anchored 字段作兼容，但由 source 派生，不再独立作为可信依据。

### 5.3 展示视图与旧结果

| 当前情况 | 展示契约 |
|---|---|
| 新来源有效，引文匹配 | 附简历引文，展示引文，可回跳 |
| 来源删除、改文或无效 | 来源已变化，待核对；不显示当前有效标记 |
| source=none | 作答思路，无简历引文；不显示回跳 |
| 旧结果没有 source | 旧版要点，来源未复核；保留原内容 |
| 畸形来源字段 | 降级为来源不可用，不抛错、不写盘修复 |

证据表身份仍由 ID/指纹决定，不因模型引文失配删除有效 ref。展示引文若不能匹配真源，不作为已核对原文展示；素材按已确认 facts 读取，facts 为空时明确没有可展示事实，不能退回模型 quote 或表达层充当事实。

展示状态在现有 `jobViewLive` 位置即时计算，不批量迁移 meta，不改写旧结果，不新增导出门禁。“附简历引文”只说明引文可定位，不宣称要点语义已由程序证明。

### 5.4 岗位评估

`/eval/create` 只输入母版与 JD。先用 `docToText(html,{includeHidden:false})` 取得可见正文，prompt 与 parser 必须使用这同一字符串。新报告状态为 covered/partial/missing：

- covered 必须有可核验原文；缺引文或不命中降级 partial，并清空引文。
- partial 可保留模型判断；非空引文也必须核验，不命中只清引文。
- missing 不保留证据引文。
- 新模型仍输出旧 sourced 时，兼容解析为 missing、清空引文，记录兼容原因。
- 历史 sourced 读时显示旧版来源未核验；不称“素材支持”，不修改原始存储、历史 score/verdict，不猜测素材出处。

新评估记录增加 `source={type:'resume',docId,hash}`；hash 使用 `contentHash` 对上述可见正文计算，不能哈整份 HTML。没有 source 的旧记录明确来源未复核。保持现有评估同步调用、失败不落半条记录，不新增历史列表或评估任务系统。

## 6. 实际资源容量与重试

### 6.1 单一池、占用与所有权

新增小模块 `resource-slots.mjs`，在每个服务进程内唯一创建并导出 AI 池与 render 池，容量分别为 2；服务端与 LLM 客户端导入同一实例。它只提供立即申请、合法性/借用检查、幂等释放及统一资源繁忙错误，不增加等待队列。

一个占用凭证只能同时借给一个实际执行器；可顺序复用，不能通过一个凭证隐藏多个并发请求。跨池、已释放和正在并发借用的凭证必须拒绝。

| 层 | 所有权 |
|---|---|
| 同步业务入口 | 在写盘/调用前预留；等待全部业务工作结束，在 finally 释放 |
| startGenTask | 先检查现有业务限制，再申请 AI；写 running 失败则释放；成功转交 runner |
| runGenTask | 接管生成凭证，最外层 finally 释放，HTTP 返回不影响它 |
| chat、renderCurrent | 仅透传，不申请、不借用、不释放 |
| chatMsgs、renderDoc | 有凭证只借用；没有时自行申请并在真实工作结束后释放 |
| HTTP 关闭、取消接口、超时触发回调 | 不直接释放 |

同步 AI 和岗位生成共用物理 AI 容量。原有元数据锁内同类任务最多 1、所有生成合计最多 2 的业务限制仍然生效。业务冲突保持 409；物理容量不足返回 429，未启动的新任务不能留下 running。

chatMsgs 的借用持续到响应正文读取、JSON 解析和格式检查结束；renderDoc 的借用覆盖全部本地尝试及子进程终结，不能在拿到响应头或发出终止信号时提前结束。

### 6.2 渲染覆盖与提前预留

`renderDoc` 是当前文档、快照和投递存档的共同兜底，`renderCurrent` 只负责冻结、临时文件和记账。入口与底层使用同一个凭证，避免重复占位和自锁。

必须登记的现有渲染入口：

| 方法 | 路径 |
|---|---|
| GET | `/pdf`、`/export`、`/snapshot/pdf` |
| POST | `/render`、`/export`、`/export/layout-apply`、`/app/add`、`/app/archive-regenerate`、`/rollback`、`/restructure` |

`/restructure` 预留 AI 和 render；组合申请失败返还已取部分，既不调用模型也不修改文档。同一 `/export` 的顺序渲染复用凭证；本地渲染失败重试也共享凭证。

容量拒绝必须发生在该请求的业务写入前，正文/meta/投递/快照/PDF 均无本次写入。底层兜底不能代替有写操作入口的提前预留。`WRITE_ON_GET` 仍单独维护，承担维护锁语义，不与资源容量合并。

本轮保持现有渲染超时和一次本地失败重试，不顺手调整数值。发出 kill 不代表子进程已经退出，必须等 close 后才开始下一次尝试或释放。error、timeout、close 统一单次结算；确认没有启动进程的异常可以直接失败。

### 6.3 断连、取消与请求体

已开始的同步工作在客户端断开后继续收敛，保留占用直到完成；响应已销毁时不再写响应。后台生成的 HTTP 结束不结束 runner。

逻辑取消保持“结果不再落账”，底层仍运行时继续占用。物理超时、abort 或 kill 之后仍以请求 Promise 或子进程实际终结为释放边界。不承诺上游已经停止生成或停止计费。

提前预留后，收请求体也必须可终结：`readBody` 对 aborted/error 和未完整收完的 close 单次失败，正常结束不误判；读之前已断开也立即失败。监听器与占用均能清理，不悬挂未完成 Promise。

容量只覆盖当前进程拥有的工作，不限制独立 CLI、其他服务进程或远端取消后不可观测的执行。

### 6.4 模型重试

每次模型 POST 只发送一次，连接拒绝、响应前断连、超时、4xx、5xx、解析和格式失败均不自动重发。`status===undefined` 或 fetch failed 不能证明未送达。

失败提示本次未完成、未自动重试；送达/完成未知时如实表达，提供明确人工重试入口，不声称未计费。GET 模型列表保留有界重试；明确取消不重试。供应商幂等键和费用核对另立需求。

## 7. 验证、兼容与交接

### 7.1 退出码与严格模式

浏览器测试退出码：0=所有计划检查完成且通过；1=任一断言失败；2=仅浏览器环境不可用且此前没有失败。参数错误不得返回 2。已有失败优先级高于环境跳过。

最终交付入口固定为 `RESUME_TEST_STRICT=1 npm run test:all`，沿用当前四套件聚合。严格模式下必需浏览器段和冻结件基线验证不能跳过；正常开发模式允许明确报告环境跳过。缺少真实个人简历的可选 smoke 仍可跳过，交付不依赖私有数据。不得通过搜索输出中的“跳过”两个字判定测试状态。

### 7.2 测试实例与进程

主服务、LLM 桩、JD 桩和故障副本使用本轮端口及临时目录。若保留显式 PORT 指定，被占用时直接失败，不杀占用者。端口探测到启动之间如发生竞争，安全重选或报错，不转而清理其他进程。

每次启动立即登记子进程 PID；正常、失败、中断均只终止并等待本轮子进程。故障副本用完立即回收，不能重用变量遗忘旧进程。日志、请求记录全部在 TEST_DIR，不再写共享固定 `/tmp` 文件。测试入口中的残留绝对导入改成项目内相对定位。

### 7.3 CSP 兼容

支持范围为当前模板，以及当前历史白名单对应的两种不同主脚本指纹。历史脚本从 Git 已知版本取得并保留原字节，制作虚拟文档夹具；运行测试不依赖 Git 历史存在，也不从真实 docs 复制个人内容。

每个版本均验证：未知脚本不执行；真实键盘编辑；点击主脚本绑定的保存按钮；保存请求成功；隔离磁盘含标记；刷新后仍有标记、未知脚本仍未执行。不用直接 fetch 或测试侧补绑定替代主脚本行为。

预期 CSP 拒绝可能产生控制台信息，应与未捕获页面异常区分。保留严格 CSP，不扩大白名单、不删除失败断言来取得通过。

## 8. 执行组织、停止条件与回退

### 8.1 责任边界

| 文件/职责 | 编辑所有权 |
|---|---|
| `server.mjs` | 单一服务端集成 owner，按工作包串行合并 |
| `zone-panel.js`、相关编辑器注入辅助与区域纯函数 | 区域 owner；服务端接线交集成 owner |
| `evidence.mjs`、`eval.mjs`、`job-panel.js` 来源展示 | 来源 owner；不得同时改任务完成出口 |
| `llm.mjs`、`resource-slots.mjs` | 资源 owner；服务端路由/runner 接线交集成 owner |
| `test.sh`、`test-editor.mjs`、`test-structure.sh` | 单一验证 owner 接各包反例；不要多人同改共享测试文件 |
| 历史脱敏夹具 | 可独立准备，测试接入交验证 owner |
| README、handoff、路线图 | 文档 owner 最后回写实际交付结果 |

独立模块与夹具可并行准备。共享文件的修改顺序由 owner 控制，不按行号分多人同时编辑。整套验收由一个 owner 运行并记录；不把只读设计子代理报告当作动态验证结果。

### 8.2 依赖顺序

1. 固定本设计契约、支持历史清单和用例编号。
2. 先修验证退出码与隔离基础，确认能检出预设失败。
3. 处理区域安全应用和任务状态；来源纯函数、资源模块及历史夹具可独立准备。
4. 服务端 owner 依次接区域提交、任务状态、来源视图与评估、资源准入；测试 owner 接入对应行为用例。
5. 相关反例与兼容行为通过后，执行一次严格四套件；仅因新变更、失败或未解决风险补跑。
6. 回写实际验证、剩余限制和发布步骤；真实服务更新后才可声称对用户生效。

实施时发现无法满足关键不变量，应停止该包集成并说明证据，不能通过放松 CSP、修改冻结件、忽略失败或扩大可信声明收尾。

### 8.3 回退

按工作包形成可单独回退的提交，保护其他 agent 与用户已有改动。新增字段采用可选与读取默认，不执行真实数据批量迁移；回退业务包后保留新增数据但不解释其为更高可信度。

区域操作失败走现有事务恢复；不得把整个旧页面快照写回覆盖后续输入。代码回退不恢复“按端口杀进程”、自动模型 POST 重发或放宽 CSP。无法保留安全保证时暂停相关操作入口并明确原因，不伪造完成。

实施 agent 按项目纪律重启真实服务并用真实浏览器做用户可见行为检查，确认没有在途用户工作后执行；真实验证不得写入真实简历，写操作放隔离实例。真实模型连通/质量验证另行授权，模拟结果标注为模拟。
