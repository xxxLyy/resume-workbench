## 1. 目标与不做

目标：主题层与样式来源登记；typo 归一为 meta 唯一来源；冻结渲染契约（快照/存档自包含、永不读当前 meta）；含正文的渲染版本标识与统一陈旧判定；HTML 与 meta 一致提交/回滚/复制/备份成对；schemaVersion 迁移事务；状态维度拆分与权威来源；导出不可变产物；视觉回归门禁；I-8/I-9 收尾。

不做：多模板（S6）、区域绑定（S3）、换肤（S2）、编辑器模板版本升级（`data-editor` 仍 v5）。

## 2. 渲染输入与冻结契约（铁律两条）

1. **当前文档渲染** = 当前 HTML + 该文档当前 meta（theme/typo）。由 server 组装"渲染输入 HTML"（doc html + 注入 meta.typo）写临时文件，交 `render.mjs --src`。
2. **快照、投递存档及任意 `--src` 渲染** = 只使用冻结文件中的内容与样式，**绝不读取当前文档 meta**。`render.mjs` 保持 meta-blind（不读 docs-meta、不注入 typo）；server 的存档/历史路径直接以冻结文件为 --src。

**两种 HTML 的规范格式**：
- **冻结文件**（快照/存档/历史产物）：内联 typo、自包含、**只读**；渲染时直接使用该文件，不套当前 meta。
- **当前可编辑文档**（docs/<id>.html）：落盘**不含** typo-custom，typo 值只存 meta；`<style>` 带来源属性。
- **复制/回滚**：读取冻结文件 → **归一化为当前格式**（剥离内联 typo-custom 提取为 meta.typo；登记其 `<style>` 来源属性与 styleHash）→ 写当前文档 + meta；禁止把冻结文件直接 copy 成当前文档。
- **freezeHtml 语义**：对当前文档一律以对应 meta 为准（若检测到当前文档仍含 typo-custom，视为未归一化，先归一化再冻结）；对冻结文件输入不注入、不改写。不存在"已有 typo 就跳过注入"的分支。

**统一冻结方法 `freezeHtml(id)`**（新模块 `freeze.mjs`）：输入当前 html + meta，输出 `{ html, bodyHash, cssHash, typoHash, renderInputId }`；html = 归一化后的当前 html + 内联 meta.typo + 确保 `<style>` 带来源属性。**所有冻结点必须调用它**：`snapshot()`（server.mjs:97）、岗位来源快照（:520）、`/version/create`（:574）、投递冻结（:699）、`/duplicate`（:484，freeze + 继承 meta）、`/rollback` 恢复归一化（:971）、备份合并成对处理（:1626/1640/1646/1689）。

"没有微调"是合法历史状态：冻结文件不含 typo-custom 即表示当时无微调，渲染不得回填当前 meta。

## 3. 样式来源登记与主题块识别（前提修正）

既有文档内联 CSS ≠ 模板 CSS（实测差异见前置事实）。故：

- 既有文档**保留实际内联 CSS**；迁移时给其 `<style>` 补属性 `data-style-origin="legacy-inline"`，登记 `meta.theme='legacy'`、`meta.styleHash=sha1(该 CSS 文本)`。不重写内容。
- 新建文档内联 `themes/resume-classic.css`（唯一源），`<style data-theme="classic">`，`meta.theme='classic'`、styleHash 同算法。
- S6 切换模板的查找锚点 = `<style>` 上的 `data-theme` / `data-style-origin` 属性（既有文档迁移后必有其一）；**用户主动切换才替换旧样式**（先快照）。
- `renderInputId` 的 cssHash 取**渲染输入中实际 CSS** 的哈希（legacy 文档即其 legacy CSS），不假设等于 themes 文件哈希。

## 4. 渲染版本标识与统一陈旧判定

- `renderInputId = sha1(bodyHash + ':' + cssHash + ':' + typoHash + ':' + resourcesHash)`，**含正文**；resourcesHash 的输入 = **嵌入内容 / 不可变资源引用 / 内容哈希**（头像内嵌 base64 或其文件哈希、自托管字体文件哈希、themes css 哈希），字体族清单只进 manifest 作记录、**不作指纹**。
- 渲染任务**启动时**冻结输入与 renderInputId；成功后记录 `meta.lastRenderInputId`、`meta.lastRenderAt`（记的是**该任务**的标识，不是"当前"标识）。
- 陈旧判定（单入口 `staleInfo(id)`，/pdf、/export、/render、首页徽章共用）：`stale = 无 PDF || meta.lastRenderInputId !== currentRenderInputId(当前正文+样式+微调)`。**mtime 不再作为正确性依据**（仅日志参考），消除"渲染 A 期间保存 B"的误判。
- 母版"来源较旧"继续用**内容版本**：`job.sourceHash`（正文哈希）对比母版当前 bodyHash；renderInputId 不替代 sourceHash。
- 渲染环境旁车：render 成功写 `<pdf>.env.json` = `{ bin, browserVersion, fonts, dpi, renderInputId, at }`。**快照不强制 resolveChromium**：快照 manifest 的 chromium 字段允许 `null`（未知），环境信息只记录到实际 PDF 产物旁车。

## 5. HTML 与 meta 一致提交、回滚、复制、备份

- **保存事务**（/save，覆盖异常与进程中断）：① 以旧正文+旧 meta 调 freezeHtml 生成旧快照；② **写前持久化事务记录** `<RESUME_ROOT>/.tx/<txId>.json` = `{ txId, docId, phase, oldSnapTs, oldMetaBackup, startedAt }`（oldMetaBackup = 旧 meta 整份副本于 `.tx/<txId>.meta.json`）；③ 新 html 与新 meta 共用 `meta.rev++`，双临时文件 + 两次 rename；④ 成功 → 删 tx 记录 → 返回 200；任一异常 → 用旧快照+旧 meta 备份恢复两者 → 删 tx → 返回失败。**进程中断**（两次 rename 之间被杀）：启动时与迁移/保存重跑前扫描 `.tx/`，对未完成事务按 oldSnapTs+oldMetaBackup 恢复该文档 html 与 meta 后删除 tx；恢复只针对 tx 指名文档，**不覆盖其他文档的 meta 更新**。
- **冲突限制**：保存与迁移对目标文档持进程内文档锁；持锁期间其他写入（/save、/rollback、/duplicate、迁移）返回 409 并提示重试；既有 baseMtime 多标签机制保留。
- **验收新增**：在两次 rename 之间 `kill -9`，重启后该文档无正文/排版混版、其他文档 meta 更新不被覆盖（隔离根 + 注入式 kill 脚本）。
- **回滚**（/rollback:971）：恢复冻结 HTML → 从冻结 HTML 解析回写 meta（typo = 内联 typo-custom 文本、theme/styleHash = 其 `<style>` 属性与哈希）→ rev++；`deliveredRefs`/exports 历史不变。
- **复制/岗位版**：/duplicate 复制 meta 条目（theme/styleHash/typo/rev 语义继承、rev 重置为 1）并以 freezeHtml 产出副本 html；岗位来源快照走 freezeHtml（:520）。
- **备份合并/替换**：同一文档的 html 与 meta **成对处理** —— 取备份 html 必同时取备份 meta 的 theme/styleHash/typo/rev；replace 模式整对替换；merge 冲突以备份为准时亦整对。
- 改造清单（S1 范围）：server.mjs:97、484、520、574、699、971、1626、1640、1646、1689。

## 6. 迁移：schemaVersion 与完成状态事务

- 版本字段分离：**编辑器版本** = template `data-editor`（S1 不动，仍 v5）；**数据格式版本** = `meta.schemaVersion`（1→2）+ `meta.migration = { state: 'done'|…, at, checks }`。M1 总计划中"v5→v6"措辞同步改为"schemaVersion 1→2、编辑器版本不变"。
- 事务（逐文档）：先快照 → 提取 typo 入 meta 并从 html 删除、补 `<style>` 来源属性、登记 theme/styleHash/renderInputId 初值 → 跑三项检查（文本层 0 差异、页数同、视觉 ≤0.5%）→ **全过才**写 `schemaVersion=2`、`migration.state='done'`；任一失败 → 恢复该文档 html+meta 完整旧状态并报告，不阻断其他文档。
- 半完成识别：以 `.tx/` 事务记录 + `schemaVersion` 联合判断 —— **有未完成 tx = 中断** → 先按 tx 恢复再重做；**无 tx 且 schemaVersion<2 = 首次迁移** → 直接进入迁移，**不回滚历史快照**。不以字段存在或文本相同判断完成。
- 事务（逐文档）：先快照 → 写 tx → 提取 typo 入 meta 并从 html 删除、补 `<style>` 来源属性、登记 theme/styleHash/renderInputId 初值 → 跑三项检查（文本层 0 差异、页数同、视觉 ≤0.5%）→ **全过才**写 `schemaVersion=2`、`migration.state='done'`、删 tx；任一失败 → 恢复该文档 html+meta 完整旧状态并报告，不阻断其他文档。迁移前全量副本 `backups/pre-s1-<ts>/`。

## 7. 状态模型、旧值映射与权威来源

- `kind`: `'master' | 'job'`（文档类型）。
- `flow`: `'draft' | 'reviewing' | 'reviewed'`（流程状态）。
- `archivedAt`: `null | ts`（**独立归档标记**，不混入 flow）。
- **可投递 = 派生**：`flow==='reviewed' && 无 pending 事实冲突 && !staleInfo(id).stale`；不存储。
- `deliveredRefs` 与 `exports[].usedBy` **不存储**：读取时从 `applications.json` 派生（**权威来源 = applications.json**，每条投递含 docId/snapTs），消除三处关联维护。
- 旧值映射（迁移写回，兼容读即时推导不写回）：`job.status 'draft'` → flow `'draft'`（若 job.changes 存在 pending → `'reviewing'`）；`'deliverable'` → `'reviewed'`；`'delivered'` → `'reviewed'`（投递历史改由 applications 派生）；无 job 的母版 → `'draft'`。迁移完成后**删除 `job.status`**（单源），避免新旧两套状态被不同页面读写。
- 归档接口：新增最小 `POST /archive`（置/清 archivedAt），home 列表默认隐藏 archived（可切换显示）。

## 8. 导出记录与不可变产物

- 用户导出（**仅 POST /export**）生成不可变产物 `pdfs/history/<id>@<renderInputId>.pdf`（**完整哈希**命名，不用 8 位截断）；**文件存在即复用，禁止覆盖**既有不可变产物。
- `exports[] = { exportId, snapTs(冻结快照引用), renderInputId(完整), file, at, jobId, bodyHash, pages, theme }`；`exportId` 为全局唯一关联键。
- 投递记录（applications.json 条目）需要关联导出时保存明确 `exportId`；`usedBy`/`deliveredRefs` 仍为读取时派生视图（权威 = applications.json）。
- 同 renderInputId 的重复导出（重复点击/重试）复用既有 exportId 与产物，**不产生重复记录**；渲染或写记录失败不记 exports。GET 打开导出页不记。
- `pdfs/<id>.pdf` 仍为"最新版"便利文件（/pdf 直链），可被覆盖；历史记录与投递存档**不指向它**。
- 配额清理：history 产物、**被 exports 引用的冻结 HTML、manifest 及必要资源**一律豁免（沿用快照保护规则并扩展到 manifest/资源）。
- "是否仍对应当前内容" = 派生：`renderInputId === currentRenderInputId && bodyHash === 当前 bodyHash`，不存储。

## 9. 视觉回归门禁（补强）

- 环境记录：bin 路径 + `chrome-headless-shell --version` 实际版本 + 字体族清单 + **栅格化 DPI 固定 150**（`pdftoppm -r 150`）。
- 像素差异算法：逐页同尺寸 PNG 逐像素比较，`diff像素 / 总像素 ≤ 0.5%` 为通过（`tools/pixel-diff.mjs`，S1 新建）；文本层 0 差异与页数相同为硬门禁。
- 验证顺序：**先在隔离副本**（真实数据 cp 到 `RESUME_ROOT=<tmp>`）跑通迁移与三门禁 → 再对真实数据迁移。
- 基线 manifest（新快照伴生）：`{ theme, styleHash, typoHash, renderInputId, editorVersion, chromiumBin: null|…, browserVersion: null|…, fonts, dpi, createdAt }`；旧快照无 manifest 不回补。

## 12. v3.1 契约增补（实施依据，normative）

1. **资源指纹完整内容哈希**：内嵌 `data:` 资源哈希**完整数据**；本地文件引用（头像/字体等）哈希**文件内容**；可变外部资源（http(s) URL）= **不可复现输入** —— `freezeHtml` 返回 `remote: [urls]`，普通渲染允许但 `<pdf>.env.json` 记 `reproducible:false`，**POST /export 拒绝**并提示先本地化。前缀截断（前 64 字符）禁用。
2. **当前文档渲染唯一入口**：所有当前文档渲染（POST /render、/export、/pdf 的缺失/过期自动重渲）一律经 freeze 组装（HTML+meta）；**/pdf 不再直接渲染磁盘 HTML**。**GET /edit** serve 时注入当前 meta.typo（保存时再提取归一），否则保存后刷新编辑器丢排版显示。
3. **共享 meta 原子更新**：统一入口 `updateMeta(root, docId, patchFn)` —— 提交前读最新 docs-meta.json、只更新目标文档字段、双临时+rename；/save、/job/changes、渲染完成回调、/tag、/archive、迁移全部改用它；事务恢复只恢复目标文档。迁移与保存另持**跨进程排他锁** `<root>/.migrate.lock`（open 'wx' + stale 超时）；server 见锁时对写请求 503。真实迁移二选一：停常驻服务或持有该锁。
4. **视觉门禁前置**：像素比较工具在**首次完整迁移之前**就绪；实际迁移三项（文本/页数/视觉）全过才写 `migration.state='done'`；检查器缺失（pdftoppm/ffmpeg 不在）= **停止提交**，不降级；单元测试可注入模拟检查器。
