> 实施计划：`dev-docs/2026-09-23-s0-plan.md`

## 1. 根因（实测）

- `render.mjs:36-49` 与 `test-editor.mjs:18-24` 是**同一处硬编码的两份拷贝**：`find "$HOME/Library/Caches/ms-playwright/chromium_headless_shell-1223" …`。
- 本机缓存实测只有 `chromium_headless_shell-1234` / `-1243`；playwright-core 1.60.0 的 browsers.json 期望 1223。
- 实测 `node render.mjs --src … --out …` → `chromium_headless_shell-1223 未找到`，exit 3，无产物。所有导出/投递存档/`/render` 失效。
- 服务日志：plist `StandardOutPath=/tmp/resume-server.log`，文件当前不存在；丢失原因**待核实**（/tmp 清理为假设）。

## 2. 设计

### 2.1 单一探测出口 `chromium.mjs`

生产渲染（`render.mjs`）与浏览器级测试（`test-editor.mjs`）共用，保证两者用同一二进制（评审要求）。

- `expectedRevision()`：读 `node_modules/playwright-core/browsers.json` 的 `chromium-headless-shell.revision`（当前 1223），不再硬编码。
- `candidates()` 顺序：① `RESUME_CHROMIUM`（若设置）；② 期望修订号目录；③ 其余 `chromium_headless_shell-*` 按修订号**降序**。
- `probe(bin)`：真渲染一页含 `RESUME-PROBE-中文文本层` 的 HTML → `pdftotext` 校验该串存在。目的：挡住 macOS CoreText 文本层丢失 bug（`render.mjs:39` 旧注释记载），探针不通过即不可选。
- `resolveChromium({tmpDir, force, waitMs})`：缓存有效直接返回；否则加锁逐候选探针，首个通过者写缓存；全失败抛错并列出每个候选的失败原因。

### 2.2 缓存与失效规则（评审收口项）

缓存文件 `<RESUME_ROOT>/.chromium-choice.json` = `{bin, source, revision, playwright, ok, probedAt}`。

失效触发（任一即重探）：
1. 缓存 `bin` 不存在（浏览器被删）；
2. `revision` ≠ 当前 browsers.json 期望值，或 `playwright` 版本变化（依赖升级）；
3. `RESUME_CHROMIUM` 设置值与缓存 `bin` 不一致；
4. 使用期 `chromium.launch` 失败 → 调用方 `invalidateCache()` 后 `resolveChromium({force:true})` 重探**一次**，仍失败才报错；
5. 探针失败永不写缓存。

显式语义：`RESUME_CHROMIUM` 指向不存在的路径 → **直接报错**（指明该环境变量），不静默回落候选。

### 2.3 探测互斥（锁）

- 锁文件 `.chromium-choice.json.probe-lock`；`LOCK_STALE_MS = 120000` 视为死锁可抢。
- 未抢到锁的调用方**只轮询缓存**（默认 `waitMs=30000`），**不对候选再发探针** —— 即不会出现"对尚未完成探测的渲染器并发探针"（评审收口项）。
- 轮询超时抛 `另一个进程正在探测 Chromium，稍后重试`。

### 2.4 接入点改动

- `render.mjs`：删除 `chromiumPath()`；`resolveChromium()` 取 bin；launch 失败 → 失效重探一次（2.2 规则 4）。其余逻辑（临时文件+原子替换+<1KB 判废）不变。
- `test-editor.mjs`：删除其 `chromiumPath()` 拷贝；`resolveChromium()` 失败 → 打印 `⚠️ Chromium 不可用，跳过浏览器级验证` 并 **exit 2**。
- `test.sh:386-390`：exit 0 = 通过；exit 2 = 跳过（⚠️）；其他非零 = `fail`。与脚本注释"可选，需要本机 Chromium"的语义对齐。
- `server.mjs` 无需改：它经 `spawn(node render.mjs …)`（server.mjs:106-109）间接获得新探测。

### 2.5 日志目录与轮转

- plist：`StandardOutPath/StandardErrorPath` → `/Users/xxxly/resume/logs/resume-server.log`；`EnvironmentVariables` 增 `RESUME_LOG_FILE` 同值（供服务端轮转知晓文件位置）。
- 新模块 `logrotate.mjs` 导出 `rotateLogIfNeeded(file)`：`size > 50MB` 时 copytruncate —— 读尾部 2MB 写 `file.1`，`truncate(file, 0)`。launchd 以 O_APPEND 持有 fd，truncate 后追加安全；启动时与每 24h 各检查一次（`setInterval`，unref）。
- 轮转失败只 `console.error`，不影响服务。

### 2.6 隐私检查与首次提交

- `.gitignore`（全量）：`node_modules/ config.json applications.json materials.json docs-meta.json docs/ snapshots/ pdfs/ backups/ logs/ photos/ audio/ .chromium-choice.json .chromium-choice.json.probe-lock .gstack/ *.log`。
- `privacy-check.sh`：① 必须是 git 仓库；② 敏感路径逐一 `git check-ignore` 生效；③ `git grep` 扫描**全部已跟踪文件**（仅排除夹具 `test.sh test-render.sh config.example.json`，其含虚拟号码 `138****0000`/虚拟 baseURL）匹配手机号/常见邮箱/`sk-`/非空 apiKey；命中即失败并列出行。dev-docs 不豁免：若命中按"文档红改"处理后再跑。
- 首提交只含代码、测试、模板、dev-docs、README、package 文件、plist 示例、privacy-check.sh、.gitignore。

### 2.7 首次启动检查与演示数据约定

- `doctor.mjs`（只读，不触发网络连接测试）：数据目录可写；Chromium 选择（缓存优先，`--probe` 才现场探针）；pdftotext/pdfinfo；模型配置**字段完整**（与"连接成功"严格区分，连接测试由用户主动触发）；无需模型也能用的能力清单；最近一次备份。硬失败 exit 1 并给具体修复动作。
- 演示数据约定：演示/试用 = 独立 `RESUME_ROOT` + 复用 `test.sh` 夹具生成虚拟数据；与真实数据目录天然隔离（RESUME_ROOT 机制既有）。演示模式 UI（标注模拟结果）在 M2/M3 收尾，S0 只落约定与夹具可用性。
