## 2. 护栏补漏

改动落在 `job.mjs` 的 `factGuard()`（当前 18 行，2 处调用：`job.mjs:106` 岗位改写、`zone.mjs:165` 区域改写）。**两处调用自动同时生效**，不需要分别改。

### 2.1 lostNums —— 原文丢数字（`conflict` 级）

**现状**（`job.mjs:69-87`）只有三项检查：

| 检查 | 方向 | 现状 |
|---|---|---|
| 改写新增数字 `added` | 单向 ✅ | 有 |
| 原文丢失日期 `lostDates` | 单向 ✅ | 有 |
| **原文丢失数字** | — | **❌ 缺失** |
| 非退化下限（长度/数字保留率） | — | ❌ 缺失（不做，见 §2.2） |

**改法**：`replace` 分支内加一条，与 `lostDates` 对称。

```javascript
// 现状（job.mjs:66）—— 不动
const NUM_RE = /\d+(?:\.\d+)?%?/g;

// 新增：数字归一化，展开中文数量单位
function normNum(n) {
  const m = /^(\d+(?:\.\d+)?)(千|万|亿)?(%)?$/.exec(n);
  if (!m) return n;
  const scale = { 千: 1e3, 万: 1e4, 亿: 1e8 }[m[2]] || 1;
  return String(Math.round(parseFloat(m[1]) * scale)) + (m[3] || '');
}

// lostNums：原文出现、改写后归一化集合里没有的数字
const afterSet = new Set((c.after.match(NUM_RE) || []).map(normNum));
const lostNums = [...new Set((c.before.match(NUM_RE) || []).map(normNum))]
  .filter((n) => !afterSet.has(n));
if (lostNums.length) notes.push('原文数字未原值保留：' + lostNums.join('、'));
```

**验收标准是行为不是代码形状**，实现可再简化。

**必须复现绿的反例**（调研已实跑）：

```
原文：将 QPS 从 300 提升到 5000，延迟从 80ms 降到 15ms，覆盖 3 个业务线，服务 12 万日活用户
操作：全部删除
现状：normal（静默通过）❌
目标：conflict「原文数字未原值保留：300、5000、80、15、3、12」
```

**误报控制**：
- `12万` 与 `120000` 必须判为同一个数字（`normNum` 的作用）
- `2021.03-2024.06` 里的年月同时被 `lostDates` 和 `lostNums` 命中，**允许重复报**——两条文案不同（`日期` / `数字`），指向的是「原文信息丢失」这同一事实

**连带影响**：`added` 检查（`job.mjs:72-73`）目前用未归一化的原始值比对。若把 `normNum` 同时套到 `added` 的两侧，`12万 → 120000` 这类改写不再被误报为「引入新数字」。**这是收紧不是放宽**，但会改变现有行为，实施时必须跑一遍现有断言确认无回归。

**实施时的另一处修正**：`NUM_RE` 原本在匹配时就把「万/千/亿」切掉了，`normNum` 根本看不到单位。已把 `NUM_RE` 改为 `/\d+(?:\.\d+)?\s*[千万亿]?\s*%?/g` 捕获单位。同时 `normNum` 在**无单位时不做整数化**——否则 `Math.round` 会把 `1.5` 变成 `2`、`2021.03` 变成 `2021`。

**level 定 `conflict`**：S4a 契约下 `conflict` = 导出前必须人工处理。已确认接受由此带来的正常精简被拦一次的代价。

### 2.2 非退化下限 / 空口径数字 —— 本轮不做（已确认）

三条不做的理由：

1. **空口径数字**（「提升30%」vs「从300提升到5000」）纯程序判不了真假：合法的「效率提升30%」和编造的在字符串上完全一致。规则化只能判「纯百分比且同句无基线」，误报率高，而误报一次用户就会忽略整个护栏。
2. **非退化下限**（长度/数字保留率）依赖 lostNums 先落地，先看到 lostNums 的真实误报率再定阈值，否则阈值是拍的。
3. 登记为已知缺口，`dev-docs/handoff.md` 遗留表同步。

### 2.3 scroll-padding-top —— WCAG 2.4.11（1 行）

**违规事实** `[已验证]`：

| 位置 | 事实 |
|---|---|
| `server.mjs:594` `.topnav` | `position:sticky;top:12px;z-index:50` |
| `server.mjs:2251` 快照只读横幅 | `position:sticky;top:0;z-index:1000` ← **风险更高** |
| `scroll-padding` / `scroll-margin` | 全项目零处 |
| `focus-visible` | 5 个文件都有 ✅ |

键盘 Tab 时焦点被吸进 sticky 元素底下 → WCAG 2.4.11 Focus Not Obscured（AA 级）违规。

**改法**：在 `server.mjs` 的样式块给 `html` 加

```css
html{scroll-padding-top:64px}
```

**64px 怎么来的**：`topnav` 是 `position:sticky;top:12px`，实测定义（`server.mjs:594`）为 `padding:10px 18px` + 单行内容约 40px + 2px 边框 → 底部约在距视口顶 52px，留 12px 余量。

**验收方式是浏览器实测，不是拍脑袋**：启动服务后连按 Tab，确认焦点元素完整可见不被遮。

**两个已知例外**：
- `.topnav` 是 `flex-wrap:wrap`，**窄屏会变两行**，此时 64px 偏小。窄屏下键盘导航场景少，可先不处理；若实测遮挡，用媒体查询单独加一档，不改默认值。
- 快照只读横幅（`server.mjs:2251`）是 `position:sticky;top:0;z-index:1000`，会叠在 topnav 上方，高度随内容变化。**若实测发现横幅场景仍遮挡**，用 `:has()` 针对横幅存在时单独加一档，同样不改默认值。

不写死行高（WCAG 1.4.12 Text Spacing：用户把行高调到 ≥1.5em 时不得丢内容）。

## 3. 面试指南（S4b③）

### 3.1 数据来源

**主体 = S4a 已上线的「岗位要求—经历证据对应表」**，零新数据结构。

```
证据表（已上线，每行 = 要求/当前证据/状态）
   └─ 第 i 行的证据 → 面试官拿到这段会追问什么
岗位 brief + JD（已上线）
   └─ 通用问题的语境
```

追问链本质是**证据表的下一问**，不是独立生成。

**通用问题**单独一组（自我介绍 / 为什么选我们 / 项目深挖），不锚定具体证据行。理由：小红书「面试准备」搜索结果几乎条条绑具体场景（ICBS、港城 mkt、龙湖校招…），**没有一个通用面试工具有量** → 必须绑具体岗位，通用问题只作为补充。

### 3.2 交付物

每条 = **追问链 + 答法要点**（已确认）：

| 字段 | 含义 |
|---|---|
| `question` | 第一问 |
| `followUp` | 再往下会问什么（CAR 向下追问，对应 104 HR「AI 只能潤飾單點」那条） |
| `answerPoints[].text` | 答法要点，**用户自己的话**，不是成稿 |
| `answerPoints[].quote` | 该要点对应的**原文子串**，用于程序验证 |

**AI 不生成成稿答案**。理由：小红书焦虑原话「别人帮我改过的，不像我的风格，让我脱口而出就得重新熟悉」——生成成稿会制造新的「这不是我」的距离感。

### 3.3 模型输出契约

```json
{
  "chains": [{
    "evIndex": 0,
    "question": "…",
    "followUp": "…",
    "answerPoints": [{ "text": "…", "quote": "…" }]
  }],
  "generic": [{ "question": "…", "answerPoints": [{ "text": "…", "quote": "…" }] }]
}
```

`generic` 的要点不锚定段落，`quote` 可空（但空 quote 的要点要标注「无原文出处」，不能和锚定要点混为一谈）。

**解析要容错**：坏 JSON / 缺字段 → 返回 `null`，调用方降级为「未生成」，**不假装成功**（与 `parseJobOps` 现有契约一致）。

### 3.4 护栏（两道，都零模型调用）

```
① 锚点子串验证
   normalize(quote) 必须是锚定段落正文（该 zid 对应节点）的子串
   不存在 → 丢弃该要点，并计数
   整条链要点全被丢弃 → 该链不渲染，标「无可用要点」
   ⚠️ 不静默丢弃、不假装成功

② factGuard 校验（**只查「新增」方向**）
   对 answerPoints 拼接文本跑 replace 分支，**传 `{ checkLoss: false }`**
   before = 锚定段落正文，after = 要点拼接
   只有「出现原文没有的数字」= 编造 → 标 `guard: conflict`
   ⚠️ **不查丢失方向**：答法要点天然是提炼，漏数字是精简不是编造
   （实施时实测发现：双向检查会让每条精简要点都误报 conflict——「我负责存储层」
     对上「QPS 从 300 提升到 5000」的段落必然漏数字，是正常精简不是造假）

两道护栏的取舍依据（已确认）：① 抓「编造引用」，② 抓「编造数字」，都是单向编造检测。
② 复用 §2.1 补漏后的 factGuard，通过新增的 `checkLoss` 选项区分「改写保真」与「要点提炼」两个场景，本轮不做新机制。

**为此 `factGuard` 签名变为 `factGuard(c, opts = {})`**，`opts.checkLoss` 默认 `true`（原有两个调用点 `job.mjs` 与 `zone.mjs` 行为不变）。
```

论文依据：Slobodkin et al. ACL 2024（arXiv:2403.17104），细粒度 span 归因使人工核查耗时降约 50%。

### 3.5 stale 判定

复用 S4a 的 `baseSnapshot` 机制：

```
生成时记 docRev
正文变化 → 标「来源已变化，需重新核对」（与现有 ref-stale / batch-stale 同一口径）
        → 给「重新生成」按钮
        → 不自动重跑
```

参照 `job-panel.js` 现有 `CONS_LABEL` 的 `ref-stale` 措辞，保持一致。

### 3.6 UI 位置

**并入「要求与证据」段底部的 `<details>` 折叠区**（已确认）。理由：

1. 数据源与证据表同源，物理相邻
2. **不加工具栏、不加段切换**，`reviewPos` 语义不变
3. **任务完成判定不受污染**：S4a 定的是「有终点的任务」，完成标准 = 事实冲突已解决 + 必要重点已处理 + 正文已保存 + PDF 对应当前版本。折叠区展开与否**不计入**

```
▼ 面试追问（按需生成，不影响导出）
    [生成面试追问]          未生成
  ⟳ 正在生成…              running，复用 schedulePoll

  ▼ 项目A（证据表第 1 行）
      问： 你负责的是哪一块？
      再问： QPS 再翻十倍瓶颈在哪？
      • 我负责存储层改造           [回跳]
      • 瓶颈从磁盘转到缓存         [回跳]
```

- `[回跳]` = zid 定位 + Custom Highlight 闪烁，**与 `job-panel.js:706` 现有机制同源**（瞬态，不落盘，不给正文挂 class）
- 折叠区用 `<details>`，`data-ed-inj` 或 `data-job-panel` 标记，DOM 挂 `JOB-INJECT` 注释对之间（遵守 S2 起的注入纪律）

### 3.7 边界与降级

| 情况 | 行为 |
|---|---|
| 无证据表 | 折叠区不出现，提示先生成要求与证据 |
| 无 JD | 只生成 `generic`，证据派生部分为空，标注原因 |
| 无模型 / 无 API Key | 降级文案，**不假装**（与现有 `GT_LABEL.error` 口径一致） |
| 生成中断 | 保留已生成部分（若有），允许重试 |
| 未接受任何改动 | 锚定母版正文，不是岗位草稿 |

**导出永不依赖面试指南**（S4b 原话「按需生成、不阻塞导出」）。
