## 1. 目标与不做

目标（路线图 S2 原文 + v4.1 修正）：统一设计变量与可读性验收（**仅应用 UI**）；首页首屏「继续上次任务 / 针对岗位生成」且 hero 不挤占主操作；恢复上次草稿/编辑位置/缩放/面板状态；导航/文档卡/看板/复盘/设置/编辑器外壳统一换肤；基础编辑能力（查找替换/基础格式/项目复制与删除恢复/聚焦/快捷键提示）接入统一撤销栈；线稿插画 SVG 入仓。

不做：
- 不改投递 PDF 样式（决策 2）；**不改简历正文样式与排版口径**——`.sheet` 内的标题、正文、行高、段距、版式一律由文档主题 + `meta.typo` 决定，S2 不触碰（修正 3）。
- **不清洗、不重写既有文档的内联主题块**；不在 serve 链路上对文档 HTML 做任何样式变换（修正 1）。
- **不改 `template.html`**（v2.2 新增）：护栏版本仍 v5、不安排迁移。既存每份文档都自带内联保存脚本与 ⌘S 监听，改模板只影响新建文档；因此保存清理、瞬态剥离、快捷键门控一律落在 `editor-shell.js`（注入层）+ `server.mjs` 的 `/save` 归一化 + `extract.mjs` 标记表，使新旧文档同权（§6.2）。
- 不重写撤销逻辑（兼容式接入）；**不承诺"全局单一撤销栈"**——原生输入与程序操作两套栈并存，⌘Z 按 §6.1 的**受信任输入计数器 + op 计数快照**判定是否消费程序化 op，并如实标注（修正 4 / v2.2）。
- 预设与分享副本**仅预留设计位、不展示无效入口**；业务能力/路由/数据契约不变（docs-meta **不新增存储字段**）；不做多模板（S6）。

## 2. 设计 token（作用域 = 应用 UI，排除简历正文）

两层 token，单一来源，组件层只引用不写死：

| 层 | 位置 | 现状 → S2 |
|---|---|---|
| 应用页面 | `server.mjs` page() 的 `/*A-VARS*/:root{…}`（:293）+ page() 内联组件样式 | 冷灰/靛蓝（`--bg:#F4F5F8`、`--indigo:#5B5DE8`）→ 杂志 token |
| 编辑器与面板 | `editor-shell.js` 注入块内 `body.ed-on` 的 `--ed-*`（:27）；`ai-panel.js`、`job-panel.js` 各自注入样式中的字面色（实测字面色出现次数：editor-shell 49、ai-panel 28、job-panel 21） | `--ed-*` 换杂志值；两个面板改为**引用同一组 `--ed-*`**，不再各写各的字面色 |

- 杂志 token：`--bg:#F6F1E7`（奶油纸感）、`--ink:#26221C`、`--mut:#6E675C`、`--line:#E2D9C8`、`--accent:#C2410C`（橙 CTA）、`--ok/--warn/--err` 保留语义但调暖、`--radius`/`--shadow` 调纸感；新增 `--serif:"Songti SC","Noto Serif CJK SC","Source Han Serif SC",serif`，`--sans` 沿用现有 PingFang 栈。
- 标题（h1/hero/文档卡标题/面板标题）用 `var(--serif)`；应用 UI 正文保持 `--sans`。
- **字面色清扫范围**：page() 内联组件样式、editor-shell.js / ai-panel.js / job-panel.js 注入样式中的组件层字面色 → token 引用。
  **排除清单（不计入"清零"）**：① token 声明行本身（`:root{…}`、`body.ed-on{--ed-*…}`）；② 文档主题 `themes/*.css` 与既有文档内联副本；③ 自绘 SVG 资产（优先 `currentColor`/变量，允许资产内自带色值）。
- 对比度门禁：**只约束应用 UI token**（正文/次要文本/链接对底 ≥4.5:1、CTA 文字 ≥4.5:1）；token 定值时用人工表 + 脚本校验，不达标改 token 而非改组件。`.sheet` 内正文对比度不进门禁。
- 可读性下限（字号 ≥13px / 行高 ≥1.6）同样**只对应用 UI**；简历正文的字号行高由 typo 面板与主题决定，S2 不改其口径。
- **v2.3 视觉定稿（用户 2026-09-29 看 T0 对照稿后确认）**：方向（奶油底 + 墨色 + 橙 CTA + 系统衬线）通过，附三处微调，作为硬约束写进实施计划全局约束 14——① 编辑器画布底色 `--ed-bg:#F0EBE2`（原拟 #EAE1D1 偏重，降低大面积米黄存在感），纸张仍白，首页底色/正文色/橙色不变；② 编辑器按钮主次：`导出 PDF`（`#pdfBtn`）为橙色实心主按钮，撤销/保存/查找/岗位等操作一律中性描边或轻底（撤销按钮不得比主任务抢眼），首页「继续上次任务」保持主按钮；③ 衬线只用于标题类（首页大标题、文档卡标题、分组/面板标题），按钮、表单、输入、条目名、提示正文一律无衬线，左右栏正文 13px/1.6，条目名用省略号而非频繁断行；简历纸张内样式不动。静态稿另修两处内容：删除「待绑定段落（S3 才启用）」占位；AI 示例改为事实不变的压缩表达（不得把"参与"改成"主导"——那正是决策 6 禁止的事实替换）。

## 3. 编辑器外壳样式：运行时覆盖，不动冻结件（v2 核心决策，替换 v1 §3）

问题不变：编辑器外壳样式（`.edit-toolbar/.page-line/.recovery-bar/.toast` + `@media print` 隐藏行，`themes/resume-classic.css:64-111`）住在主题文件里，因而被冻结进每份文档内联副本；legacy 文档（真实两份）内联的是旧版外壳样式。

**否决 v1 的"serve 时剥离内联外壳段"**：`/save` 上送的是浏览器整页 HTML（`server.mjs:874-882`），serve 阶段删掉的样式在下一次保存时就**永久消失**——等于被动改写冻结内容、`renderInputId`/`styleHash` 漂移，违铁律一。

采用方案（三段，全部落在既有机制上）：
1. **既有文档内联样式一律原样保留**：不清洗、不重写、不 serve 变换；`themes/resume-classic.css` 的编辑器外壳段**保留不删**（因此既有 classic 文档 `styleHash` 不变，无标识漂移——撤回 v1"styleHash 因此变化"的说法）。
2. **新外壳只走运行时限定作用域 CSS**：`editor-shell.js` 已有 `<style data-ed-shell>` 注入通道（整块包在 `@media screen{…}`、选择器带 `.ed-on` 前缀），且 `/save` 已按 `data-ed-shell`/`data-ai-panel`/`data-job-panel` 属性剥离（`server.mjs:880-882`）→ 注入样式永不落盘、永不进 PDF。S2 只改这块注入 CSS 的视觉值，并对既有 `.edit-toolbar/.page-line/.recovery-bar/.toast` 做**视觉兜底覆盖**（背景/边框/字体/圆角/阴影/间距），不删除、不修改文档内联规则；注入位于文档内联之后 → 层叠覆盖生效。关键属性不依赖 `!important`，确需使用必须就地注释原因。
3. **print 规则以冻结件自带为准，渲染端清理仅补充**：`themes/resume-classic.css:111` 的 `@media print` 隐藏行**保留**；既有文档内联副本里的 print 规则同样保留。注入层整块 `@media screen`，print 不生效。`render.mjs` 的 print-sanitize 只作为"极旧冻结件内联缺 print 规则"的兜底补充，**不得成为唯一保障，也不改变历史渲染政策**（冻结件在项目外被打印/直接渲染时仍应无工具栏）。**v2.1：该兜底为条件项**——实施计划 T2 Step 5b 先只读实测既有文档是否全部自带 print 隐藏规则；若全部自带（预期如此：legacy 与 classic 的内联副本同源于 `themes/resume-classic.css:111`），S2 **不改 `render.mjs`**，把该补充记入整理项，等真的出现缺规则的冻结件再做。

新增回归（不只是"文本层无工具栏文案"）：换肤前后，legacy 与 classic 各取一份文档渲染 PDF，比对**文本层 0-diff、页数一致、RGB24 像素差 ≤0.5%（DPI150，`tools/pixel-diff.mjs`）**；并 grep 断言主题文件与既有文档内联副本的 `@media print` 隐藏行都仍在。

S6 交接清单第 2 条随之更新：编辑器外壳由运行时注入统一提供；**新主题只需携带简历内容样式 + 自己的最小 print 隐藏规则**，不需要为旧文档外壳样式负责。

## 4. 首页重排与 hero

- 结构：hero 区（衬线大标题「简历工作台」+ 副题一行 + 右侧自绘线稿 SVG 插画位）高度受限（≤180px），不挤占主操作；hero 下第一行主操作 = 「继续上次任务」与「针对岗位生成」；岗位草稿六字段表单收进 `<details>` 折叠（默认闭）；文档列表紧随上首屏；状态条 6 chip 合并为**一行带优先级摘要**（例：`⚠ 1 份待结构化 · ⏰ 1 份面试提醒 · PDF 2/2 同步`），PDF 口径单一（同步/较旧/未生成）。
- **「继续上次任务」数据源 = localStorage `lastActiveDocId`**（编辑器打开时写入；mtime ≠ 最近访问，故不用 mtime 作首选）。回退链：
  1. `lastActiveDocId` 存在且文档可读 → 用它；

- 编辑位置/缩放/面板状态 = per-doc localStorage（S2 补齐 pane 与 zoom 键），与 `lastActiveDocId` 同侧。
- 插画：`assets/hero-mirror.svg` 等 2–3 个自绘线稿（人物/镜子/纸张意象，stroke 单色随 `--ink`），内联或 `<img>` 入仓；不用外链。

## 6. 基础编辑能力 + 撤销边界（v2 明确条款）

能力清单不扩范围：文内查找替换（⌘F 面板，范围 = 当前 sheet，全部替换 = 一次撤销条目）；基础格式（加粗/无序列表/链接/清除多余格式）；条目级复制与删除恢复（删除进撤销栈 + 5s Toast 双保险）；聚焦编辑（临时 class 收起左右栏）；快捷键提示弹层（`?`）。

### 6.1 撤销语义（v2.2 统一，取代 v2.1 与本节原表格的冲突表述）

**验收口径只有一套，先把它钉死：**

- 「输入 A → 加粗 A → 输入 B → 按一次 ⌘Z」的正确结果 = **撤销最近输入的 B，A 与加粗状态都保留**。这是浏览器原生撤销的自然行为，也是 S2 的唯一断言目标。
- 「撤销加粗、同时保留后来输入的 B」是**针对某个操作的定向撤销**。原生 ⌘Z 不保证做到，S2 也不承诺做到。定向撤销只对**程序化操作**提供（条目复制/删除、查找替换、区块排序、AI/审阅落盘、排版恢复），入口 = 工具条「↩ 撤销「X」」与 Toast 的「撤销」，两者绑定同一条 op。
- 因此格式化（加粗/无序列表/链接/清除多余格式）明确归**原生栈**：走 `document.execCommand(...)`，**不压程序化快照栈**。原 v2 表格里把"格式化按钮"列进程序操作行，现予以删除；原 v2"Selection+Range 手动实现、execCommand 仅用于 removeFormat"作废。理由：撤销栈是整片 `sheet.innerHTML` 快照（`editor-shell.js:322-324`），格式化一旦压栈，回退必然吞掉其后输入。`execCommand` 弃用风险照 §9 记录（`template.html:211` 的粘贴纯文本已在用同一 API 家族，本项目浏览器由 `chromium.mjs` 固定）。

**分派依据：不用"最后一次来源"这个布尔值，用可判定顺序的计数器。**

- `nativeInputCount`：正文上每次 `isTrusted === true` 的 `input` 事件 +1（真实打字与 IME 组合完成都派发受信任事件）。
- 每条 op 记录 `nativeCountAtApply` = 该 op 应用完成时的计数快照。
- ⌘Z 仅当 `nativeInputCount === 栈顶.nativeCountAtApply`（该 op 之后没有新的受信任输入）时消费栈顶；否则**不拦截**，交回原生撤销。
- **程序化变更的识别 = 合成 `input` 事件（`isTrusted === false`）**。这一点是硬事实：`ai-panel.js:160`、`job-panel.js:139/142` 自己派发 `new Event('input',{bubbles:true})`，**不经过外壳私有的 `notifyEdit()`**（`:318`），事件形状与外壳完全相同——任何"来源布尔值"方案都会把 AI/审阅改动误判成原生输入，而 `isTrusted` 天然覆盖三者。
- **同一族缺陷一并补**：`job-panel.js:150-155` 与 `:196-202` 的隐藏/显示路径改完 DOM **不派发任何事件**——既不标脏也不进撤销；S2 给它们补上 `touch()`，使程序化标记与 dirty 标记一致。
- 排版（`applyTypo`/`resetTypo`，`editor-shell.js:969-986`）与审阅/AI 落盘同理自动归入程序化，无需各自改代码。

**整片快照遇到后续输入时的保护（不得静默抹掉后续文字）：**

- ⌘Z 路径：如上，压根不消费该 op。
- 工具条 / Toast 路径：若该 op 之后已有受信任输入，点击必须**显式确认**（`window.confirm`，文案写明"其后的正文输入会一并回退"）；取消则不做任何修改。这与 `#ed-addsec` 现有 `prompt()` 阻塞式交互同风格，不新增抽象。
- **Toast 绑定 `opId`**：`__edUndoLast(opId)` 只消费 id 与栈顶匹配的那条；栈顶已变 → Toast 置为"已失效"（禁用 + 文案变化），**绝不弹别人的 op**。必须覆盖用例：「删除 A → 又做操作 B → 点 A 尚未消失的旧 Toast」，B 的结果不得被破坏（现状是栈里残留 `[S_beforeA, S_afterA]`，之后按工具条撤销会回退 B 并**复活 A 的节点**，实测确认）。
- **如实标注两套栈并存**：UI 文案不写"全局撤销"；快捷键弹层里写明"打字与格式化由浏览器原生撤销接管；程序化操作走「↩ 撤销」/⌘Z（该操作之后无新输入时）"。

### 6.2 瞬态状态与新旧文档同权（v2.2 硬约束）

- **`template.html` 零改动，护栏版本仍 v5，不安排迁移。** 事实依据：`template.html` 是文档模板，实测既存每份文档都自带内联 `doSave`（含 `:230` 的清理选择器）与自己的 ⌘S 监听；只改模板又不迁移，就只有新建文档受益，真实旧文档仍走旧逻辑。
- 因此这些行为修正一律落在三处：**① `editor-shell.js`**（serve 时注入，所有文档都拿到）；**② `server.mjs` 的 `/save` 归一化**（不依赖客户端脚本版本）；**③ `extract.mjs` 的 `CHROME_MARKERS`**（服务端第二道防线）。
- ⌘S 的 IME 门控：在注入层用 **document capture 阶段监听 + `stopPropagation()`** 实现——文档内联监听是 `document` 上的 bubble 阶段，capture 必然先跑，defer 注入的先后不影响这一点（已验证）。测试不引入生产钩子：用 Playwright 统计 `/save` 请求数 + CDP `Input.imeSetComposition` 造真实组合态。
- 瞬态清单：查找高亮（改走 CSS Custom Highlight API，**不改 DOM**）、聚焦模式（`body` 上的 `ed-focus` 由**服务端 `/save` 归一化**剥离，不依赖旧文档的内联清理选择器）、`flashEl` 的临时高亮（**改走 Highlight API，根因消除**：现在它给正文节点挂 `ed-flash` class 且保存链路不清理）、选区浮动工具条与快捷键弹层（继续走 `mount()` 的 `<!--SHELL-INJECT-->` 注释对通道 + `data-ed-inj`）。
- **断言方式**：落盘 HTML 必须先解析成 DOM 再检查 class/id/属性，**不得用磁盘子串包含判断**——保存脚本自身的文本就含这些字符串，会造成必然误报（已复现）。

## 7. 验收

1. **统一设计变量**：page()、editor-shell.js、ai-panel.js、job-panel.js 的组件层样式无字面色（按 §2 排除清单实现 grep 断言）；全站截图无冷灰/靛蓝残留。
2. **编辑器外壳一致性**：legacy 与 classic 文档在 `/edit` 下**关键控件（工具条、状态条、toast、页线、左右面板标题）的 `getComputedStyle` 采样值一致 + 截图视觉一致**；不再要求"外壳样式字节一致"。
3. **冻结件不变性**（修正 1）：稳态下（先保存一次完成既有归一化）只打开编辑器并保存、不改正文与排版 → 落盘 HTML 的主题 CSS 块、正文内容、`styleHash`、`renderInputId` 全部不变（哈希断言）；瞬态标记检查必须**解析落盘 HTML 的 DOM** 后查 class/id/属性，不得用磁盘子串包含（保存脚本自身文本含这些字符串，会必然误报）。
4. **渲染等价回归**（修正 2）：换肤前后 legacy 与 classic 各一份 PDF，文本层 0-diff、页数一致、像素差 ≤0.5%；主题与既有内联副本的 `@media print` 隐藏行仍在。
5. **可读性/对比度门禁（仅应用 UI）**：token 对比度表全过；同时断言 S2 未改 `themes/*.css` 的简历内容样式段与 typo 口径（修正 3）。
6. **业务能力/路由/数据契约兼容**：路由集合不变、docs-meta 无新增存储字段、既有 API 请求/响应形状不变（test.sh 覆盖）。
7. **既有撤销零回归 + 新增用例**：`test-editor.mjs` 常驻套件全绿；五件基础编辑各有撤销往返用例；并覆盖以下编辑用例——
   - 「输入 A → 加粗 A → 输入 B → 一次 ⌘Z」：撤销的是最近输入的 B，**A 与加粗状态都保留**（§6.1 钉死的口径）；
   - 「程序操作 → 继续输入 → 连续 ⌘Z」：⌘Z 不得消费该程序化 op（不得整片回退吞掉后续文字），程序化 op 仍可通过工具条入口经确认后撤销；
   - 「删除条目 A → 又做操作 B → 点 A 尚未消失的旧 Toast」：B 的结果不得被破坏，A 的 Toast 必须进入"已失效"态；
   - 跨加粗节点替换（选区横跨 `<b>` 边界替换，不破坏结构、不丢字）；
   - 查找不得跨块级边界产生虚假命中（上一段结尾 + 下一段开头拼成的假命中必须不存在），正文变化后命中位置必须重算，替换前必须二次校验目标文本；
   - 跨章节选区操作不破坏结构（选区覆盖两个 section 时格式化后 DOM 结构与 section 数不变）；
   - 链接协议校验（`javascript:`/`data:` 拒绝并提示；允许 http/https/mailto）；
   - 输入框内输入 `?` 不触发快捷键弹层（仅正文/无输入焦点时触发）；
   - 中文 IME 组合期间不触发快捷键（`compositionstart/end` 门控；组合中 ⌘Z/⌘S 不误触发；⌘S 用 `/save` 请求计数验证，不引入生产钩子）。
   **夹具纪律**：每组用例使用自己有效的独立夹具（必须真的含 `.section`/`.entry-head` 等结构，能让被测试的按钮存在）；关键按钮或元素缺失一律判 `bad()`，**不得记 `ok()` 跳过**。
8. 窄屏单栏不破（既有 viewport CSS 回归截图）。
9. **Task 0 两屏静态对照稿确认门**：home hero + 编辑器外壳两屏先出稿（隔离根截图），用户确认后才铺全站。
10. **新旧文档同权（v2.2 新增）**：涉及保存清理、瞬态剥离、快捷键门控的行为修正，验收必须包含**升级前已存在的文档形态**（自带旧内联脚本的文档），不得全用新模板生成的夹具代替；由于 `template.html` 零改动，注入层 + 服务端归一化必须对两类文档产生同样的落盘结果（用"同一文档在修正前后各保存一次，解析 DOM 后瞬态清单一致"断言）。

## 9. 风险

- 注入层覆盖与文档内联层叠冲突 → 注入位于内联之后 + `.ed-on` 作用域 + `getComputedStyle` 断言；避免 `!important` 滥用（用则注释原因）。
- 冻结件被动漂移 → 禁止一切 serve 端样式变换；T2 以哈希断言做门禁（§7.3）。
- 撤销双栈并存造成期望落差 → 按"最后一次变更来源"分派并在 UI 如实标注，不承诺全局单一撤销。
- IME/选区被程序操作破坏 → 组合期门控 + 跨节点/跨章节用例常驻。
- execCommand 弃用 → 仅 removeFormat 使用，风险记录，S3 再议。
- token 换肤后对比度不达标 → 门禁在 token 定值时即校验，不改组件救火。
