# S5 设计定稿：引导建档向导 —— 服务端承载（2026-11-02）

> 上游：roadmap §S5（v3/v4 评审定稿的 8 步约束）。本卡 = 设计定稿 + 服务端路由 + 草稿文档承载暂存；
> 卡片流交互 / STAR 逐条引导 UI / 照片注入模板属 S5 前端卡，本文登记其合同。
> 核心架构决策（已定，不翻案）：**向导进度不新建文件** —— 早期就创建一份真实草稿文档承载，
> 每步确认即写入该文档（复用 /save 语义与区域初绑），**暂存 = 文档自然存在**；
> 「空输入不产出脏文档」由「**首步确认前不建文档**」保证。

## 1. 八步信息架构（roadmap 原文约束的落地映射）

| 步 | 名称 | 写入目标 | 服务端行为 |
|---|---|---|---|
| 0.1 | 基础信息 | header（h1 / contact / intent） | 写档 |
| 0.2 | 画像与方向 | 个人总结 | 写档 |
| 0.3 | 经历补充 | 工作经历 + 项目经历（entry-head + ul/li，同 structure.mjs 形状） | 写档 |
| 0.4 | STAR 结构化 | 工作经历（逐条 STAR 要点，允许跳过）+ 事实层暂存 | 写档；facts 记 meta.onboarding.facts |
| 0.5 | 软性信息 | 专业技能 + 教育经历 | 写档 |
| 0.6 | 证件照（可选） | photos/（用户数据目录，排除 Git） | 存文件 + meta 记录（注入模板=前端卡） |
| 0.7 | 预览微调 | —（复用编辑器 /edit） | 只推进度 |
| 0.8 | 生成与导出 | —（走既有导出链路 /edit → /export） | 收口 finished |

- 八步是**可跳过的组织方式**：每步可跳过（显式 skip 与空载荷等价）、可暂存续作；服务端只校验「不回退」，向前跳步合法。
- 事实层（0.4）按 roadmap {事实、条件、个人贡献、来源} 录入，落 meta.onboarding.facts 暂存（含来源标注）；
  与 S3 素材库（materials.json / FACT_KEYS）的合并属前端卡，合并时逐条带来源、不自动转写表达层。
- 每步左线描插画（assets/hero-*.svg 经 svgAsset 内联，零新静态路由）+ 情绪文案、右确认卡片流；
  本卡页壳为 page() 风格零 JS 表单流（POST → 303 回 /onboarding?docId=），与卡片流共用同一 API 合同。

## 2. 暂存机制（草稿文档承载）

- **建档时机**：某步「合并预填后仍有内容」且尚无文档 → 当步落档；纯跳步/空载荷 → 不建档（响应 docId:null）。
- **产出与手建文档完全同权**：assembleTemplate('classic') + themeRegistration + kind=master / flow=draft，
  与 POST /new 逐字段同款；id 分配同 /new 方案；首页列表自然可见，删除/快照/导出/投递全走既有链路。
- **每步写档 = /save 语义的最小复刻**（同原语不另起灶）：stripInjections → normalizeZids（缺失补，zid 纪律）→
  normalizeToCurrent → beginTx/atomicWrite/updateMeta/commitTx（异常双恢复）→ dropSupersededTx；
  updateMeta 内 rev+1 + zoneSync（**区域初绑**：新写内容即刻获得 zid 与 zones 绑定）。不打快照（同 autosave 口径，配额）。
- **步进进度存 meta[id].onboarding**：{last, next, skipped[], prefillFrom?, facts?, photo?, finished}；
  无文档阶段进度由客户端持有（无服务端状态可丢——这正是「不新建文件」的含义）。
- **步序校验**：step 必须 ∈ 0.1–0.8（400）；step 早于 last（回退）→ 409（提示去文档直接编辑）；
  step == last 允许（同请求重试幂等：重写同区域同内容）；docId 非 VALID_ID → 400；文件缺失 → 404；
  非 onboarding 文档（无 meta 记录）→ 409（防误写母版）；finished 后再步进 → 409。
- **续作**：GET /onboarding?docId= 渲染进度（步骤条 done/skip/current）与当前步表单；
  已完成态展示 /edit 与 /export 入口。锁/错误体沿用全局口径：迁移根锁 503、文档锁 LockHeld → 409 {ok,retry,error}。

## 3. 预填规则（已有简历 → 只补缺失）

- 入口：payload 带 `prefillFrom=<母版id>`（任意步可用，VALID_ID + 存在校验，缺失 404）。
- 提取 = **纯确定性文本结构提取**（零 AI、零外联）：stripInjections 后按 h1 / .contact / sectionsOf(标题)
  取「姓名 / 联系方式+意向 / 各区域 inner HTML」；跳过 hidden 区域；摘除 data-zid（新文档由 normalizeZids 重打，
  不携带母版的区域绑定）；信任边界与 /duplicate 同级（不剥正文脚本，/edit CSP 兜底）。
- **只补缺失**：合并规则 = 用户本步 payload 字段非空者胜，空缺位由母版对应内容填充；
  响应带 `prefilled:[字段]` 供 UI 只呈现缺失项、不要求确认未变化信息（产品目标原文）。
- 「是否有内容」按**合并后**判定：母版可填出内容即视为有内容（此时建档不属脏文档——内容全部来自用户既有文档）。

## 4. AI 审阅门控（本卡不接模型，合同先行）

- 向导的 AI 整理（0.4 STAR 逐条）只准**整理用户已确认的散料**：prompt 输入仅含用户确认过的事实文本；
  禁止补造经历、禁止生成用户未提供的时间/数字（走 S4a 既有事实护栏与 evidence 子串校验，不另写一套）。
- AI 产出**必须经确认卡逐条接受**才落档，不自动写入；每条产出标注来源（用户输入 / 母版提取 / AI 整理）。
- AI 不可用 = 纯手填路径完整可用（向导永不阻塞在模型上）；真实模型验证需用户授权（既有纪律）。

## 5. 照片方案（0.6，可选）

- payload.photo = data URL（png/jpeg/webp，≤5MB）→ 解码存 `photos/<docId>.<ext>`（0600）；
  photos/ 启动即建并落 `photos/.gitignore`（`*` + `!.gitignore`）——**不改仓库 .gitignore 即排除 Git**；
  meta.onboarding.photo 记 {file, bytes, type}。未选照片 = 跳过，零副作用。
- **注入模板 = 前端卡**：template.html 冻结且无照片槽位，注入方案（编辑器注入层 or 模板决策）另卡定；
  本卡只负责「存入用户数据目录并排除 Git」。photos/ 暂不入备份清单（登记：恢复不含照片，待前端卡一并定）。
- 无文档时提交照片 → 400（照片需先有文档承载；全跳步到达 0.6 属边缘，文案引导回 0.1）。

## 6. API 合同

- `GET /onboarding[?docId=]`（`/onboarding/guided` 为 roadmap 原文别名，同 handler）：page() 页壳。
- `POST /onboarding/step`：body {step, payload?, docId?, prefillFrom?, skip?}（JSON 与表单双兼容，
  表单行式简表 `名称 | 职位 | 时间` + `- 要点` 解析为 entries）；成功 → `{ok:true, docId, step, nextStep, created?, prefilled?}`；
  失败 → `{ok:false, error}` + 语义状态码（400/404/409/503）。0.8 成功响应带 editUrl。

## 7. 验收清单（夹具 test-onboarding-api.mjs，隔离根 + 桩 LLM）

1. 无文档首步空载荷 → 不建档（docs/ 零新增文件），响应 docId:null —— 空输入不产出脏文档。
2. 逐步写档：0.1→0.2→0.3 每步落档可见（header / 个人总结 / entry 形状），进度 last/next 正确。
3. 跳步：0.1 后直取 0.3 → 合法，skipped 记 '0.2'，被跳区域保持模板默认。
4. 步序门：回退 409；未知步 400；非 onboarding 文档 409；finished 后 409。
5. 暂存退出重进恢复：GET /onboarding?docId= 渲染进度；按 docId 续作 0.5 成功。
6. 预填只补缺失：payload 已填字段胜出，母版只填空缺；prefilled 如实登记；母版字节零改动。
7. 产出文档 GET /edit 可开、含 `var DOC_ID`；meta kind=master / flow=draft（与手建同权）；首页可见。

## 8. 边界（本卡不做）

卡片流/插画情绪文案的最终稿与逐条编辑 UI、STAR 逐条引导、AI 整理接模型、照片注入模板、
首页与编辑器的向导入口、母版合并进素材库——均属 S5 前端/后续卡；本卡 API 已为其预留合同位。

**① STAR AI 整理合同（POST /onboarding/star-suggest）**：
- 只产建议卡、绝不写文档——确认门控是结构性的：正文只认 POST /onboarding/step（用户确认后的载荷）。
- prompt 显式约束：只整理用户给出的原文，不得补造经历/公司/时间/数字；无原文依据的字段必须输出空串；
  只输出 JSON `{"entries":[{"index":1,"star":{"s","t","a","r"}}]}`。
- 解析守卫（不信任模型输出）：截取首个大括号区间容错；未知/越界 index 丢弃（不产新条目）；空字段丢弃；
  每字段截断 300 字、最多 20 条。
- 资源闸门：路由纳入 AI 闸门（gatePool → aiPool，并发 ≤2、满则 429），lease 经 leaseOf(req) 透传 chat。
- 桩友好：未配置模型 → 409 `{ok:false, code:'NO_LLM'}`，UI 按钮显示失败文案并回落纯手填（该步可跳过）。
- UI：0.3 经历卡内「AI 套 STAR」按钮（仅已有文档承载时渲染）→ 建议只回填卡片 s/t/a/r 输入框（可改），
  点「确认并下一步」才随步骤载荷落正文。

**事实层结构（随文档保存）**：`meta.onboarding.facts = { at: ISO 时间, items: [{subject, fact, condition,
contribution, source}] }`（subject=经历名称、source=来源标注；单步 ≤50 条、字段截断 200/2000 字；
只含至少一个非空事实字段的条目）。与正文同事务落 docs-meta.json（obWriteDoc / 建档路径）；表达层（要点）
在正文、事实层在 meta，二者分离；与素材库（materials.json / FACT_KEYS）合并仍属后续卡。
