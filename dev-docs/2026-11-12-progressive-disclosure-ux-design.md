# 渐进呈现 UX 重设计（spec）

> 2026-11-12 ｜ 状态：用户已批准 mockup ｜ 批准件：`dev-docs/2026-11-12-ux-progressive-disclosure-mock.html`
> 动机：用户裁决——「项目太复杂，没到方便使用的程度；最好是第一次使用的人都知道应该怎么使用」。
> 前置结论（同对话）：上云/多用户方向暂缓；先做可用性。复杂度来源裁决 = 主流程太长 + 界面信息太密 + 概念太多。
> 取舍裁决：**藏，不砍，不动数据模型**（用户在藏/中度/彻底三档中选了最保守档）。

## 0. 目标与边界

**目标**：首次使用的用户不看文档就知道下一步做什么；老用户的功能一个不丢。

**边界（不做清单，继承项目纪律）**

- 不动数据模型：docs-meta / applications / apply-profiles / 文档正文格式零改动，零迁移。
- 不删功能：所有页面保留且 URL 不变，只改导航与入口组织。
- 不加 npm 依赖；冻结件 `template.html` / `render.mjs` / `themes/` 零改动。
- 不做多用户、账号、云部署（方向另议，本文不含）。
- S7/S9 维持用户裁决不做；ATS 恐吓分等既有「明确不做」清单继续有效。
- 可见变化先登记 DESIGN.md 再改（产品原则「登记再改」）；撞既有测试按 R3① 先例：意图不变的用例适配，断言零放宽，适配与实现同提交。

## 1. 信息架构：导航 6 项 → 3 项

```
现在:  文档 | 素材库 | 投递看板 | 复盘 | 设置 | 网申包
改后:  简历 | 投递 | 设置
```

| 移出项 | 新落点 | 页面状态 |
|---|---|---|
| 素材库 | 编辑器左栏（本已存在「可用素材」区） | 页面保留，导航移除 |
| 网申包 | 投递看板内入口（页签或卡片入口） | 页面保留，导航移除 |
| 复盘 | 投递看板内入口（页签或卡片入口） | 页面保留，导航移除 |

- 「文档」改名「简历」——导航说用户的事，不说系统的事。
- 「投递看板」改名「投递」。
- topnav 唯一原则不变（DESIGN.md 既有裁决）；UI-5「不得回归 sidenav」断言不受影响。

## 2. 首页：状态驱动，只展示「下一步」

首页不再展示全部功能。展示内容由真实数据状态决定（读现有 docs-meta / applications，**零新数据字段**）。

### 状态 0：无任何文档

- 一句话标题 + 两张选择卡：「导入现有简历」（拖入 PDF）/「从零开始」（分步向导）。
- 下方一份简历缩略图作为产品样品（全站唯一 rich 元素，见 §5）。
- 不出现：统计块、搜索框、看板、日程、任何状态计数。

### 状态 1：有简历、无投递

- 首屏 = 「继续」卡：文档缩略图 + 名称 + 更新时间 + 状态点 + 人话状态行（如「PDF 不是最新，导出时会重新生成」）。
- 主操作：「继续编辑」（黑）+「导出 PDF」（橙）。
- 「接下来可以」引导卡一张：→ 为岗位定制（一句话解释「按 JD 生成定制副本，母版不动」）。
- 全部文档列表（行式，非大卡）+ 底部小字入口：新建空白 / 导入 PDF。

### 状态 2：有投递（求职中）

- 顶部「待办」卡：人话句 + 行内动作（例：「『字节-感知算法』的 PDF 还是旧版 → 重新导出」「面试已过 3 天 → 起草跟进语」）。替代现在的黑话计数区（待结构化 / PDF较旧2 / AI: minimax / 待办提醒数字块）。
- 简历列表：母版与岗位副本同列，各行带状态点。
- 近期日程保留，逾期项给动作入口（不只是红点）。
- 新建入口只在底部一行：为岗位定制 / 新建空白 / 导入。

**入口去重**：「为岗位定制简历」在首页只出现一次（状态 1 在引导卡、状态 2 在底部新建行；现在的顶卡 + 底栏双入口取消）。

## 3. 文案规则：去黑话

面向用户的文本一律用人话。映射示例（非穷举，实施时全量过一遍）：

| 现在的说法 | 改成 |
|---|---|
| 待结构化 | 还没整理成结构化简历 / 待整理 |
| PDF较旧 | PDF 不是最新，导出时会重新生成 |
| 待办提醒 | （并入待办卡的人话句） |
| AI: minimax | 不在首页出现（留在设置页） |
| 评估↦投递 | 评估到投递的转化（仅在复盘内部，复盘不在本轮范围可暂缓） |
| 投递看板 | 投递 |
| 文档 | 简历 |

页脚与品牌统一为「简历工作台」（现在 logo 与页脚不一致）。

## 4. /job/new：双栏表单 → 1-2-3 单动线

```
1 岗位描述   一个大 textarea（粘贴全文）；「或粘贴招聘页链接」是小字切换
2 用哪份简历  一行确认条（只有一份母版时直接显示名+「更换」，不是下拉表单）
3 生成       黑主按钮「生成岗位草稿」+ 小字次选「先评估匹配度」
```

- 删除：公司、岗位两个必填输入——从 JD 文本提取（AI 已具备解析能力）。提取产物用于草稿命名；提取失败或无配置时草稿名落「未命名定制」，进编辑页可改。
- 「本次定制要求」保留为可折叠「补充要求（可选）」。
- 「先评估这个岗位」降级为次级链接，不与主按钮平级（消岔路）。
- 生成前给诚实预期：「约 2–3 分钟，分批改写并校验。产出一份新草稿，可再编辑。」（继承诚实文案原则）。
- 后端管线（analyze→locate→rewrite→validate→assemble 五阶段、分批、幂等重试）**零改动**，只改该页的 HTML/交互组织。

## 5. 视觉语言（unslop 裁决）

现有 palette 与字体不动（暖灰 ramp + 单一橙 accent + Lucide 是定案，非 slop）。本轮新增三条规则，登记进 DESIGN.md：

- **按钮语义**：黑 = 主操作；橙 = 只给「导出 PDF」（与编辑器现状一致）。
- **状态点系统**（signature）：7px 圆点 + 文字，贯穿全站——灰 = 草稿、橙 = 需要你处理、绿 = 已投出。替代现有各色徽章/黑话标签。
- **文档缩略图**（moment）：首页与列表中的文档卡用真实渲染缩略图；本期可先用 CSS 绘制的示意缩略（mockup 同款），真实渲染缩略图若成本超支可降为后续项。

审计出的其余项（编辑器四区密度、网申包 42 操作点、复盘空态文案）**本轮不修**，原因：编辑器深挖成本高且风险大，网申包/复盘已因导航下沉而降低曝光——移到下一轮单独立项。

## 6. 测试与验收影响

- 导航结构、首页区块、/job/new 表单结构变更会撞既有断言（topnav 项数、首页元素、表单字段、CSP 内联脚本）。按 R3① 先例处理：意图不变的用例做适配，断言零放宽，适配与实现同提交。
- 新增断言方向：状态 0/1/2 首页分支各一（渲染存在性 + 不该出现的元素确实缺席）。
- /job/new：JD 文本域为唯一必填；公司/岗位字段不再出现。
- 文案：黑话词（待结构化、PDF较旧、投递看板、待办提醒）不出现在首页响应 HTML。
- 全量 `RESUME_TEST_STRICT=1 npm run test:all` EXIT=0 收口。

## 7. 已定细节与范围备忘

1. **「投递」页承载方式 = 页签**。看板 / 网申包 / 复盘三个子页签复用编辑器页签模式，登记 DESIGN.md。
2. **本轮缩略图 = CSS 示意**（mockup 同款）。真实渲染缩略图列为后续项，不占本轮范围。
3. **「待办」源清单**：本轮覆盖三类——PDF 非最新、面试满 N 天可跟进、文档待整理；其余待办源（如日程逾期）按同一「人话句 + 行内动作」模式逐条补，不追求一次穷尽。
